# 第 10 章 知识表示（Knowledge Representation）

**本章导读**：一阶逻辑给了我们表达力，但"如何组织知识"才是工程难点。本章讨论知识表示的四个层次：本体（世界里有哪些类别）、对象与类别的关系（描述逻辑、继承）、事件与时间（事件演算、区间代数）、心理状态与模态（知道、相信、可能）。随后介绍两类"非经典"推理——类别推理系统中的继承与缺省推理——最后落到工业界最常见的形式：知识图谱与图数据库。

**学习目标**：完成本章学习后，你应当能够：

- 说明本体的作用与上层本体的设计取舍（通用 vs 专用、概念 vs 角色）；
- 用描述逻辑写出类别定义，判断包含（subsumption）与实例检查；
- 用事件演算或区间代数表示时间与因果，处理框架问题；
- 用模态逻辑刻画知识/信念，说明可能世界语义；
- 区分单调与非单调推理，写出缺省规则与封闭世界假设；
- 用 RDF/OWL/SPARQL 建模知识图谱，说明其与图数据库、向量化的关系。

**预备知识**：第 8–9 章的一阶逻辑与推理；集合论；基本的图结构。

## 10.1 本体工程

**本体（ontology）** 是对某一领域的概念化说明：有哪些**类别（class）**、**个体（individual）**、**关系（relation/role）**，以及它们的约束。

**为什么需要本体**：

1. **共享词汇**：让多个系统对"病人""订单""设备"有同一理解；
2. **支持推理**：类别层级使"所有哺乳动物都呼吸"这类知识可复用；
3. **数据集成**：不同来源的数据通过本体对齐（同一实体合并）。

**上层本体（upper ontology）**：不针对具体领域，只规定最一般的类别。AIMA 给出一个典型骨架：

| 类别 | 含义 | 子类举例 |
| --- | --- | --- |
| `Thing` | 一切 | — |
| `AbstractObject` | 抽象对象 | `Set`、`Number`、`Proposition` |
| `Event` | 有时空位置的发生 | `Process`、`Action` |
| `PhysicalObject` | 有质量与位置 | `Agent`、`Device` |
| `Agent` | 能行动者 | `Human`、`Robot`、`Organization` |

设计两个经典争议：

- **通用 vs 专用**：上层本体越通用越难有用；越专用越难复用。工程上通常"通用上层 + 领域本体"两层。
- **概念 vs 角色**：`Employee` 是人的**角色**而非类别（同一个人可以既是员工又是顾客）。用角色建模可避免"多重继承"带来的分类僵化。

**本体语言谱系**：

| 语言 | 表达力 | 可判定性 | 用途 |
| --- | --- | --- | --- |
| RDFS | 类、属性、子类 | 可判定 | 轻量级元数据 |
| OWL 2 EL | 存在限制、交集 | 多项式 | 大规模生物医学本体 |
| OWL 2 QL | 查询重写友好 | 多项式（AC⁰ 数据复杂度） | 数据库上层本体 |
| OWL 2 RL | 规则可实现 | 多项式 | 规则引擎 |
| OWL 2 DL | 完整描述逻辑 | 可判定（最坏指数） | 精确本体建模 |

**工程经验**：绝大多数项目的实际需求落在 **OWL 2 EL/QL/RL** 三个 profile 内；完整 DL 的表达力很少被用到，却带来推理性能灾难。

## 10.2 类别与对象

**语义网络（semantic network）** 是最早的图形化表示：节点是概念或个体，边是 `IsA`（子类）、`InstanceOf`、`HasPart` 等关系。它直观但语义模糊（"边"到底表示什么？），因此演化出**描述逻辑（description logic, DL）**。

**描述逻辑的基本构件**：

| 构件 | 语法 | 含义 |
| --- | --- | --- |
| 原子概念 | $A$ | 类 |
| 原子角色 | $R$ | 二元关系 |
| 交集 | $C \sqcap D$ | 同时属于 |
| 并集 | $C \sqcup D$ | 属于其一 |
| 补 | $\neg C$ | 不属于 |
| 存在限制 | $\exists R.C$ | 存在 $R$ 关系指向 $C$ 的个体 |
| 全称限制 | $\forall R.C$ | 所有 $R$ 关系都指向 $C$ |
| 数量限制 | $\ge n R.C$、$\le n R.C$ | 至少/至多 $n$ 个 |

**TBox 与 ABox**：

- **TBox**（术语公理）：概念之间的包含关系，如
$$\text{Parent} \equiv \text{Person} \sqcap \exists \text{hasChild}.\text{Person}$$
- **ABox**（断言）：个体的事实，如 $\text{hasChild}(\text{Alice}, \text{Bob})$。

**两类核心推理**：

- **包含（subsumption）**：$C \sqsubseteq D$ 是否成立——即 $C$ 的每个实例都是 $D$ 的实例；
- **实例检查（instance checking）**：个体 $a$ 是否属于概念 $C$。

它们都归约为**可满足性**：$C \sqsubseteq D$ ⟺ $C \sqcap \neg D$ 不可满足。

**推理算法**：

- ** tableau 算法**：尝试构造一个满足公式的模型，通过展开规则（$\sqcap$ 规则、$\exists$ 规则、$\forall$ 规则）检测冲突；有**阻塞（blocking）** 机制保证终止。
- **归约到一阶逻辑**：DL 是 FOL 的可判定片段（通常为二变量片段 $\mathcal{ALC}$ 等），可交给专门的 DL 推理器（HermiT、ELK）。
- **规则化**：OWL 2 RL 可编译成 Datalog 规则，用前向链接（§9.3）实现，工程上最常用。

**继承与继承网络**。类别层级天然支持**属性继承**：`Penguin ⊑ Bird`，`Bird` 有 `hasFeathers`，则企鹅继承之。但**例外**（企鹅不会飞）打破了单调性，这是 §10.6 的主题。

## 10.3 事件

世界不是静态的：动作发生、状态改变、因果相连。表示事件有三条路线。

**（1）事件演算（event calculus）**。用谓词刻画"某事件在某时发生，某性质在某时段成立"：

- $\text{Happens}(e, t)$：事件 $e$ 在时刻 $t$ 发生；
- $\text{Initiates}(e, f, t)$ / $\text{Terminates}(e, f, t)$：事件启动/终止性质 $f$；
- $\text{HoldsAt}(f, t)$：性质 $f$ 在 $t$ 成立。

公理：

$$\text{Happens}(e,t) \land \text{Initiates}(e,f,t) \land \neg\text{Clipped}(t, f, t') \Rightarrow \text{HoldsAt}(f, t')$$

优点是**单调**：新事件只需追加事实，不必修改既有公理；它把"框架问题"（什么没变）转成"默认持续"。

**（2）区间代数（Allen's interval algebra）**。用 13 种关系刻画两个时间区间的关系：`before`、`meets`、`overlaps`、`during`、`starts`、`finishes`、`equals` 及其逆。它适合**定性时间推理**（日程、叙事理解），可用约束传播（§6.2）求解。

**（3）情境演算（situation calculus）**。把"情境"作为一阶项，用函数 $do(a, s)$ 表示"在情境 $s$ 执行动作 $a$"：

$$\text{Poss}(a,s) \land \text{Holds}(f, s) \Rightarrow \text{Holds}(f, do(a,s))$$

它把动态世界编译进静态逻辑，是"规划即定理证明"的基础（§11.2）。

**框架问题（frame problem）** 是这三条路线的共同敌人：若用公理逐条声明"动作不改变什么"，需要 $O(\text{动作}\times\text{性质})$ 条公理。解法有：

- **缺省持续**（事件演算、答案集编程中的默认规则）；
- **成功公理/后继状态公理**（规划领域，§11.1）；
- **最小变化语义**（circumscription，§10.6）。

## 10.4 心理对象与模态逻辑

**命题态度（propositional attitude）**：知道、相信、想要、害怕——它们指向的不是对象，而是**命题**。用 FOL 直接写 $\text{Knows}(\text{Alice}, \text{Rain})$ 会把"命题"当成普通对象，导致**逻辑全知**问题：

从 $\text{Knows}(A, P)$ 与 $P \Rightarrow Q$ 可推出 $\text{Knows}(A, Q)$——但现实中的智能体推不出所有逻辑后承。

**模态逻辑** 用算子解决这一类问题：

- $\Box \varphi$：必然（在 epistemic 语境中读作"知道"）；
- $\Diamond \varphi$：可能。

**可能世界语义（Kripke 语义）**：

$$\mathcal{M}, w \models \Box\varphi \iff \text{对所有满足 } w R w' \text{ 的 } w',\ \mathcal{M}, w' \models \varphi$$

其中 $R$ 是**可达关系**：$w'$ 是"智能体在 $w$ 认为可能的"世界。不同的 $R$ 约束对应不同的公理系统：

| 系统 | 对 $R$ 的要求 | 公理 |
| --- | --- | --- |
| K | 无 | $\Box(\varphi \Rightarrow \psi) \Rightarrow (\Box\varphi \Rightarrow \Box\psi)$ |
| T | 自反 | $\Box\varphi \Rightarrow \varphi$（知道的事为真） |
| S4 | 自反 + 传递 | 加 $\Box\varphi \Rightarrow \Box\Box\varphi$（知道自己知道） |
| S5 | 等价关系 | 加 $\Diamond\varphi \Rightarrow \Box\Diamond\varphi$（知道自己不知道） |

**应用**：

- **多智能体知识**："Alice 知道 Bob 不知道密码"需要嵌套模态；
- **安全协议验证**：用 epistemics 证明"攻击者不知道密钥"；
- **信念修正（AGM）**：加入新信念时保持一致性，按信念的**牢固度（entrenchment）**排序，优先删除最不牢固的旧信念；
- **AI 对齐**：机器对"人类意图"的信念建模（theory of mind）。

代价是**计算复杂度**：S5 的可满足性是 PSPACE 完全，多智能体情形更高。

## 10.5 类别的推理系统

工业系统中，类别推理通常不直接用完整 DL，而是用更专门的结构。

**继承网络（inheritance network）**。节点是类别，边是 `IsA`，属性沿边继承。推理只需沿边遍历，复杂度线性。问题在于**多重继承冲突**：若 `Quaker` 与 `Republican` 都是 `Pacifist` 与 `Hawk` 的子类（Nixon 菱形），继承结果不确定。解法是**特异性优先（specificity）**：更具体的类覆盖更一般的类。

**描述逻辑推理器**：

- **表算法 + 阻塞**：判定一致性（§10.2）；
- **模块化**：把大本体拆成模块，只加载相关部分（locality-based modules）；
- **增量推理**：只重算受新公理影响的结论；
- **解释**：给出"为什么 $C \sqsubseteq D$"的证明路径——这在生物医学本体（SNOMED、Gene Ontology）中是刚需。

**规则与 DL 的混合**：**DL-safe 规则**（如 SWRL 的受限形式）把 Datalog 规则叠在 DL 本体上，兼顾表达力与可判定性。

**类别推理的复杂度**：

| 片段 | 一致性检查 |
| --- | --- |
| $\mathcal{EL}$ | 多项式 |
| $\mathcal{ALC}$ | EXPTIME 完全 |
| $\mathcal{SHOIN}$（OWL DL 基础） | NEXPTIME 完全 |

## 10.6 缺省信息推理

经典逻辑是**单调**的：加知识不会推翻旧结论。常识推理恰恰相反：

- "鸟会飞"——但企鹅不会；
- "除非另有说明，门是关着的"；
- "正常情况下，程序不会崩溃"。

这类推理叫**非单调推理（nonmonotonic reasoning）**。

**三种主流形式化**：

**（1）缺省逻辑（default logic, Reiter）**。规则形如

$$\frac{\alpha : \beta_1, \dots, \beta_m}{\gamma}$$

读作"若 $\alpha$ 成立，且各 $\beta_i$ 与当前信念**一致**，则可推出 $\gamma$"。企鹅例子：

$$\frac{\text{Bird}(x) : \text{Flies}(x)}{\text{Flies}(x)} \qquad \frac{\text{Penguin}(x)}{\neg\text{Flies}(x)}$$

由于企鹅与"会飞"不一致，第一条规则对它不适用。缺省逻辑的语义是**扩展（extension）**：一组自洽的结论闭包，可能不唯一。

**（2）限定（circumscription, McCarthy）**。用二阶公式表达"只把满足谓词 $P$ 的对象限制在必要范围内"，即**最小模型语义**。它适合刻画"正常情况下"的默认。

**（3）封闭世界假设（closed world assumption, CWA）与否定即失败（NAF）**。若无法证明 $P$，就认为 $\neg P$。这是数据库与 Prolog 的默认语义：

- **优点**：实现简单（只需证明搜索失败），查询高效；
- **风险**：知识不全时会推出错误结论；逻辑上**不可靠**（相对经典语义）；
- **正确用法**：只在领域封闭、且"未知即假"可接受的场景使用（如配置系统、权限判定）。

**答案集编程（ASP）**：用

```
flies(X) :- bird(X), not penguin(X).
penguin(tweety).
bird(tweety).
```

表达默认规则，求解器（clingo）枚举**稳定模型（stable model）**。ASP 已用于规划、配置、生物网络推理，是"非单调推理的可工程化形态"。

**与概率的关系**：缺省推理处理"定性不确定性"（不知道 vs 假），概率处理"定量不确定性"（0.8 的可能）。第 12 章起会看到，概率图模型可以统一二者的一部分。

## 10.7 知识图谱与图数据库

**知识图谱（knowledge graph）** 是以图结构组织的事实集合：节点是实体或字面量，边是关系。它本质上是 **ABox + 轻量 TBox**，通常用 RDF 或属性图表示。

**RDF 三元组**：`(主语, 谓词, 宾语)`

```
:Alice  :worksFor  :Acme .
:Acme   rdf:type   :Company .
:Alice  :age       "30"^^xsd:integer .
```

**RDFS/OWL 的推理**：`rdfs:subClassOf`、`owl:equivalentClass`、`owl:inverseOf` 支持类别归属与关系反转的自动推理；OWL 2 RL 可编译成规则做前向链接。

**SPARQL 查询**：

```sparql
SELECT ?person WHERE {
  ?person :worksFor :Acme .
  ?person :age ?age .
  FILTER (?age > 30)
}
```

**属性图（property graph）** 与图数据库（Neo4j、TigerGraph）：节点与边可带属性，查询语言（Cypher、Gremlin）更适合路径遍历：

```cypher
MATCH (p:Person)-[:WORKS_FOR]->(:Company {name:'Acme'})
WHERE p.age > 30
RETURN p.name
MATCH path = shortestPath((a)-[*..6]-(b))
RETURN path
```

**知识图谱的四大用途**：

| 用途 | 说明 |
| --- | --- |
| 实体消歧与链接 | 把"苹果公司"与"苹果（水果）"分开，跨库对齐 | 
| 检索增强 | 为问答/搜索提供结构化事实（§24.7 的 RAG） |
| 推理补全 | 用规则或嵌入模型推断缺失关系（链路预测） |
| 可解释性 | 用路径作为答案的依据 |

**知识图谱嵌入**：把实体与关系映射到向量空间（TransE、RotatE、ComplEx），用 $f(h,r,t)$ 打分做链路预测。它把符号结构转成可微表示，是"神经符号"的典型接口（附录 E.5）。局限是**难以保证逻辑约束**（如"国籍唯一"），常需加规则约束或类型约束。

**工程权衡**：

| 方案 | 优势 | 劣势 |
| --- | --- | --- |
| RDF + SPARQL | 标准、可交换、推理完备 | 存储与查询性能较弱 |
| 属性图数据库 | 路径查询快、开发友好 | 标准不统一、推理弱 |
| 向量嵌入 | 抗噪声、可泛化 | 不可解释、需再校验 |
| 混合（图 + 向量 + 规则） | 兼顾 | 系统复杂 |

## 本章小结

**核心要点**

1. **本体**规定领域的类别、个体与关系；上层本体提供通用骨架，领域本体负责细节。
2. **描述逻辑**用 TBox/ABox 分离术语与断言，推理归约为可满足性；工程上应优先选 **EL/QL/RL** 等 tractable profile。
3. 事件表示有三条路线：**事件演算**（单调、易扩展）、**区间代数**（定性时间）、**情境演算**（规划即证明）；共同难题是**框架问题**。
4. **模态逻辑**用可能世界刻画知道/相信，$R$ 的约束决定公理系统；代价是高复杂度（S5 为 PSPACE 完全）。
5. **非单调推理**处理常识例外：缺省逻辑、限定、封闭世界假设、ASP 稳定模型；它们牺牲单调性换取表达力。
6. **知识图谱**是 RDF/属性图的工程化形态，配合 SPARQL/Cypher 查询、嵌入做链路预测、规则做约束校验。
