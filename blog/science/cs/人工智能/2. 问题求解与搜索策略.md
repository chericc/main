# 第 2 章 问题求解与搜索策略

**本章导读**：搜索是人工智能中最基础的求解范式之一——下棋、规划路径，还是为变量赋值以满足约束，本质上都可转化为在状态空间中寻找从初始状态到目标的路径或最优解。本章先给出问题的形式化框架与搜索算法性能的度量标准，随后依次讨论无信息搜索、有信息（启发式）搜索、局部搜索、对抗搜索与约束满足问题六大类方法。读完本章，你应能针对具体问题选择合适的搜索策略，并说清其完备性、最优性与复杂度边界。

**学习目标**：完成本章学习后，你应当能够：

- 用初始状态、动作、转移模型、目标测试、路径代价五要素形式化一个实际问题，并区分状态空间图与搜索树；
- 说明 BFS、DFS、DLS、IDS、UCS 的数据结构、扩展顺序及完备性/最优性，并推导其时间与空间复杂度；
- 设计满足可纳性与一致性的启发式函数，运用 A*、IDA* 求解最优路径，并解释 A* 的"最优效率"含义；
- 描述爬山法、模拟退火、束搜索的机制与适用场景，并说明局部搜索与遗传算法的分工（后者见第 4 章 §4.1）；
- 运用 Minimax 与 Alpha-Beta 剪枝分析零和博弈，理解评估函数设计与 MCTS 的四步循环；
- 将问题建模为 CSP，应用回溯搜索、前向检验与 AC-3 弧相容进行求解；
- 针对同一问题比较不同搜索策略在时间、空间、最优性上的权衡。

## 2.1 问题形式化

**问题的五要素**。在搜索框架下，一个（良定义）问题由五个要素共同确定。**初始状态 (Initial State)** 是智能体出发时所在的状态；**动作 (Actions)** 是每个状态下可执行动作的集合 `ACTIONS(s)`；**转移模型 (Transition Model)** 描述执行动作后的结果，记作 `RESULT(s, a) = s'`，又称**后继函数 (Successor Function)**；**目标测试 (Goal Test)** 判断当前状态是否为目标，可由显式状态集合或隐式条件给出；**路径代价函数 (Path Cost Function)** 为每条路径分配数值代价，通常为各步代价之和 $g(path) = Σ cost(s_i, a_i, s_{i+1})$，求解目标是找到总代价最小的解。当上述五要素均被明确指定时，该问题称为**良定义问题 (Well-Defined Problem)**，其解是一组从初始状态通向目标的动作序列。

**抽象**。形式化的关键在于**抽象 (Abstraction)**——去除与现实求解无关的细节，只保留影响求解的核心要素。好的抽象应满足两点：被移除的细节不影响解的合法性，抽象后得到的动作仍易于执行。经典示例包括：**八数码问题**以 3×3 棋盘上数字方块与空格的排列为状态、空格上下左右移动为动作；**真空吸尘器世界**以房间清洁状态与吸尘器位置的组合为状态；**路径规划问题**以地图上的位置为状态、移动到相邻城市为动作、距离为代价。这些问题规模虽小，却足以暴露搜索算法的全部关键性质。

**状态空间图与搜索树**。把问题中所有状态及其转移关系抽象为图结构，节点表示状态、有向边表示动作，便得到**状态空间图 (State Space Graph)**；它在搜索前就已隐含存在，是问题固有的结构。从初始状态出发、依动作逐步展开后继节点所得到的树则是**搜索树 (Search Tree)**，它在探索过程中动态构建，形态取决于搜索策略。二者的关键差别在于：同一个状态可能经不同路径在搜索树中重复出现。例如在 Romania 地图上，Arad 可以经不同路线多次进入搜索树，因此树搜索必须依靠**重复状态检测**（闭环检测）来避免无限循环与冗余扩展。

**性能度量与策略分类**。评价搜索算法使用四个指标：**完备性 (Completeness)** 指有解时是否保证找到解；**最优性 (Optimality)** 指找到的解是否代价最小；**时间复杂度 (Time Complexity)** 通常以搜索过程中生成的节点数衡量；**空间复杂度 (Space Complexity)** 指运行所需的最大内存。按是否使用领域知识，搜索策略可分为两类：**无信息搜索 (Uninformed Search / Blind Search)** 只使用问题定义本身的信息；**有信息搜索 (Informed Search / Heuristic Search)** 借助启发式函数估计节点到目标的距离，优先探索更有希望的路径。

## 2.2 无信息搜索

无信息搜索只使用问题定义中可用的信息，不借助外部领域知识。不同算法的区别集中在一个点上：用何种数据结构维护**边缘节点 (Frontier / Fringe)**——队列、栈还是优先队列，决定了节点的扩展顺序。

### 2.2.1 运行实例：Romania 地图

本章统一采用 AIMA 经典的 Romania 地图算例。设当前在 Arad、目标为 Bucharest，各城市到 Bucharest 的直线距离启发式 `h_SLD` 如下表，它是后续启发式搜索的基础。

| 城市 | h_SLD | 城市 | h_SLD | 城市 | h_SLD |
|:---|:---:|:---|:---:|:---|:---:|
| Arad | 366 | Fagaras | 176 | Oradea | 380 |
| Bucharest | 0 | Giurgiu | 77 | Pitesti | 100 |
| Craiova | 160 | Hirsova | 151 | Rimnicu Vilcea | 193 |
| Drobeta | 242 | Iasi | 226 | Sibiu | 253 |
| Eforie | 161 | Lugoj | 244 | Timisoara | 329 |
| Mehadia | 241 | Neamt | 234 | Urziceni | 80 |
| Vaslui | 199 | Zerind | 374 | | |

本实例涉及的关键公路及里程如下：

| 路段 | 里程 | 路段 | 里程 | 路段 | 里程 |
|:---|:---:|:---|:---:|:---|:---:|
| Arad–Zerind | 75 | Oradea–Sibiu | 151 | Pitesti–Bucharest | 101 |
| Arad–Sibiu | 140 | Sibiu–Fagaras | 99 | Bucharest–Giurgiu | 90 |
| Arad–Timisoara | 118 | Sibiu–Rimnicu | 80 | Bucharest–Urziceni | 85 |

| Lugoj–Mehadia | 70 | Craiova–Drobeta | 120 | Mehadia–Drobeta | 75 |

已知最优解为 $Arad → Sibiu → Rimnicu Vilcea → Pitesti → Bucharest$，总代价 418。下文将看到 BFS 与 DFS 都找不到这一最优解，而 UCS 与 A* 可以。

### 2.2.2 广度优先搜索 (BFS)

广度优先搜索 (Breadth-First Search, BFS) 先扩展根节点，再扩展根节点的全部后继，依此类推逐层推进，因此使用 **FIFO 队列** 作为边缘。它的时间与空间复杂度同为 `O(b^d)`（`b` 为分支因子，`d` 为最浅目标深度）：时间上必须逐层走完浅层，空间上要同时保存整层节点。BFS **完备**（只要 `b` 有限且路径深度有限），且在每步代价相等的条件下**最优**；一旦步代价不等，先到达的浅层解未必最便宜。

```text
算法：广度优先搜索 (BFS)
输入：problem（含 initial、goal_test、actions、result）
输出：解路径或 failure

1.  frontier ← 队列([节点(initial, parent=null, path_cost=0)])   // FIFO
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()          // 取队首
5.      if problem.goal_test(node.state): return 解路径
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored ∪ frontier:
10.             frontier.push(child)    // 入队尾
11. return failure
```

在 Romania 实例中，若后继按 Zerind、Timisoara、Sibiu 的固定顺序生成，BFS 会先经 $Arad → Sibiu → Fagaras → Bucharest$ 得到代价 `140 + 99 + 211 = 450` 的解并返回。它比最优解 418 更贵，直观说明**不等代价下 BFS 非最优**。

### 2.2.3 深度优先搜索 (DFS)

深度优先搜索 (Depth-First Search, DFS) 总是优先扩展搜索树中最深的节点，一路到底再回溯，因而使用 **LIFO 栈**（或递归调用）。其时间复杂度为 `O(b^m)`（`m` 为最大深度），空间复杂度仅为 `O(bm)`——只需保存一条路径上的节点，内存优势显著。代价是 DFS **不完备**：遇到无限深分支或存在环的分支会陷入死循环；它也不最优。

```text
算法：深度优先搜索 (DFS)
1.  frontier ← 栈([节点(initial, parent=null, path_cost=0)])   // LIFO
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()          // 取栈顶
5.      if problem.goal_test(node.state): return 解路径
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored:
10.             frontier.push(child)
11. return failure
```

在 Romania 实例中，DFS 会沿 $Arad → Zerind → Oradea → Sibiu → Fagaras → Bucharest$ 一路深入，得到代价 `75 + 71 + 151 + 99 + 211 = 607` 的解，远非最优。该轨迹还展示了状态重复：Sibiu 同时以不同父节点进入栈，说明搜索树并不等同于状态空间图。

### 2.2.4 深度限制搜索与迭代加深搜索

**深度限制搜索 (Depth-Limited Search, DLS)** 为 DFS 设置最大深度 `ℓ`，从而避免无限深路径，但若目标深度超过 `ℓ` 就会漏解，故仍不完备。**迭代加深搜索 (Iterative Deepening Search, IDS)** 把 DLS 与 BFS 结合：逐步增大深度限制，每轮都从初始状态重新搜索。它兼具 BFS 的完备性与 DFS 的空间效率，时间 `O(b^d)`、空间 `O(bd)`。

IDS 反复重搜浅层，看似浪费，实则不然。深度限制为 `i` 时 DLS 生成 `1 + b + … + b^i` 个节点，累加所有轮次可得

$Σ_{i=0}^{d} (b^{i+1} - 1)/(b - 1) = (b^{d+1} - 1)/(b - 1) - (d + 1) ≈ b^d · b/(b-1)$。

对 $b ≥ 2$，放大因子 $b/(b-1) ≤ 2$，是与 `d` 无关的常数：绝大部分开销集中在最后一轮，前 `d-1` 轮之和只是最后一轮的常数倍。因此 IDS 的总时间仍是 `O(b^d)`，仅比 BFS 多一个常数倍，却把空间从 `O(b^d)` 降到 `O(bd)`——这正是它的核心价值。

```text
算法：深度限制搜索 (DLS)
1.  function DLS(node, limit):
2.      if problem.goal_test(node.state): return 解路径
3.      if limit == 0: return cutoff
4.      cutoff_occurred ← false
5.      for each action ∈ problem.actions(node.state):
6.          result ← DLS(子节点(node, action), limit - 1)
7.          if result == 解路径: return result
8.          if result == cutoff: cutoff_occurred ← true
9.      return cutoff if cutoff_occurred else failure

算法：迭代加深搜索 (IDS)
1.  for depth ← 0, 1, 2, …:
2.      result ← DLS(节点(initial), depth)
3.      if result ≠ cutoff: return result
```

### 2.2.5 一致代价搜索 (UCS)

一致代价搜索 (Uniform-Cost Search, UCS) 优先扩展路径代价 `g(n)` 最小的节点，用**优先队列**管理边缘。它是 BFS 在不等代价下的推广：当每步代价相等时，UCS 退化为 BFS。只要每步代价为正，UCS 就**完备且最优**，其时间与空间复杂度均为 $O(b^{1+⌊C*/ε⌋})$，其中 `C*` 为最优解代价，$ε$ 为最小步代价。

```text
算法：一致代价搜索 (UCS)
1.  frontier ← 优先队列([节点(initial, path_cost=0)])   // 按 g 升序
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()          // g 最小的节点
5.      if problem.goal_test(node.state): return 解路径   // 出队时检测
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored:
10.             if child.state ∈ frontier 且已有 g 更小: continue
11.             else if child.state ∈ frontier: frontier.replace(child)
12.             else: frontier.push(child)
13. return failure
```

在 Romania 实例中，UCS 会在第 8 步先经 Fagaras 得到代价 450 的解，但它并不立即返回，而是继续扩展更便宜的节点，直到第 10 步经 Pitesti 发现代价 418 的更优路径。这正说明：**只有"出队时检测目标"才能保证最优性**。

综合以上算法，设分支因子为 `b`、最浅目标深度为 `d`、最大深度为 `m`、深度限制为 `ℓ`，其性质对比如下。

| 算法 | 完备性 | 最优性 | 时间复杂度 | 空间复杂度 |
|:---|:---:|:---:|:---|:---|
| BFS | 是 | 等代价下是 | `O(b^d)` | `O(b^d)` |
| DFS | 否 | 否 | `O(b^m)` | `O(bm)` |
| DLS | 否 | 否 | `O(b^ℓ)` | `O(bℓ)` |
| IDS | 是 | 等代价下是 | `O(b^d)` | `O(bd)` |
| UCS | 是 | 是 | $O(b^{1+⌊C*/ε⌋})$ | 同时间 |

可以看到，只有 UCS 同时具备完备性与最优性，代价是较高的时间开销；而 IDS 在完备性与内存之间取得了最好的折中。

## 2.3 有信息（启发式）搜索

有信息搜索 (Informed Search) 利用领域知识指导搜索方向，这些知识编码在**启发式函数 (Heuristic Function)** `h(n)` 中，它估计从节点 `n` 到目标状态的最小代价。启发式的信息量越大，搜索通常越高效。

### 2.3.1 贪心最优搜索

贪心最优搜索 (Greedy Best-First Search) 始终扩展 `h(n)` 最小的节点，即"看起来离目标最近"的节点，类似于以"离目标远近"为向导的 DFS，总是朝最有希望的方向前进。它通常搜索极快，但**不完备**（可能陷入死循环）也**不最优**；最坏情况下复杂度仍为 `O(b^m)`，好的启发式可使其接近线性。

```text
算法：贪心最优优先搜索
1.  frontier ← 优先队列([节点(initial)])      // 按 h 升序
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()                // h 最小的节点
5.      if problem.goal_test(node.state): return 解路径
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored ∪ frontier: frontier.push(child)
10. return failure
```

### 2.3.2 A* 搜索

A* 搜索使用评价函数 `f(n) = g(n) + h(n)`，其中 `g(n)` 是从初始状态到节点 `n` 的实际路径代价，`h(n)` 是从 `n` 到目标的估计代价，`f(n)` 则是经过 `n` 的完整路径的估计总代价。它相当于在 UCS（只看已付出的 `g`）与贪心搜索（只看剩余的 `h`）之间取得平衡：`g` 回望过去，`h` 展望未来。

A* 的最优性依赖启发式的两个性质。**可纳性 (Admissibility)** 要求 `h(n)` 从不高估从 `n` 到目标的真实最优代价，即 $h(n) ≤ h*(n)$；在该条件下，配合闭环检测的图搜索版 A* 是**最优的**。**一致性 / 单调性 (Consistency / Monotonicity)** 是更强的条件，要求对每条边 `(n, a, n')` 满足 $h(n) ≤ c(n, a, n') + h(n')$，它体现了三角形不等式。一致启发式保证 A* 以最优顺序扩展节点、且每个节点最多扩展一次，因而效率最高。综上，A* 完备，`h` 可纳时最优，`h` 一致时达到最优效率。

```text
算法：A* 图搜索
1.  frontier ← 优先队列([节点(initial, g=0, f=h(initial))])   // 按 f 升序
2.  closed ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()               // f 最小的节点
5.      if problem.goal_test(node.state): return 解路径
6.      if node.state ∈ closed: continue
7.      closed ← closed ∪ {node.state}
8.      for each action ∈ problem.actions(node.state):
9.          child ← 子节点(node, action)     // 计算 g、f = g + h
10.         if child.state ∈ closed: continue
11.         if child.state ∈ frontier 且已有 g 更小: continue
12.         else if child.state ∈ frontier: frontier.replace(child)
13.         else: frontier.push(child)
14. return failure
```

**最优效率 (Optimally Efficient)** 是 A* 最重要的理论性质：在启发式 `h` 相同的条件下，不存在另一个最优算法能保证扩展比 A* 更少的节点。理由在于，设 `C*` 为最优解代价，对任意满足 `f(n) = g(n) + h(n) < C*` 的节点 `n`，由于 `h` 可纳，经过 `n` 的解的真实代价不可能小于 `C*`，但要保证最优性又不能排除 `n` 所在的子树，因此必须扩展 `n`。A* 恰好扩展了所有 `f(n) < C*` 的节点（以及部分 `f(n) = C*` 的节点），已达到"保证最优所必需"的极限。需强调，这一结论是相对于**给定启发式**而言的，换用信息量更大的启发式仍可进一步减少扩展。

回到 Romania 实例，A* 依次扩展 Arad、Sibiu、Rimnicu、Fagaras、Pitesti、Bucharest，仅 6 个节点便锁定最优解 418；相比之下 UCS 扩展了 12 个节点，启发式的信息量直接转化为搜索效率。与 UCS 一样，A* 也必须在**出队时**检测目标——它在第 4 步先经 Fagaras 得到 450，随后才被经 Pitesti 的 418 覆盖。

### 2.3.3 迭代加深 A*

A* 需要保存所有已生成节点，在大状态空间中内存开销极大。迭代加深 A* (IDA*) 用迭代加深规避这一问题：每一轮设定一个 `f` 值阈值 `cutoff`，DFS 过程中一旦当前节点的 `f(n) > cutoff` 就剪枝，并记录所有被剪节点中最小的 `f` 值作为下一轮的阈值。IDA* 保留了 A* 的完备性与最优性，空间降为 `O(bd)`，在八数码等问题中广泛使用。

```text
算法：迭代加深 A* (IDA*)
1.  threshold ← h(initial)
2.  loop:
3.      result, next ← DFS-F(节点(initial), g=0, threshold)
4.      if result == 解路径: return result
5.      if next == ∞: return failure
6.      threshold ← next

function DFS-F(node, g, threshold):
1.  f ← g + h(node.state)
2.  if f > threshold: return (failure, f)        // 剪枝并记录候选阈值
3.  if problem.goal_test(node.state): return (解路径, —)
4.  min_overflow ← ∞
5.  for each action ∈ problem.actions(node.state):
6.      result, t ← DFS-F(子节点(node, action), g + cost(action), threshold)
7.      if result == 解路径: return (解路径, —)
8.      min_overflow ← min(min_overflow, t)
9.  return (failure, min_overflow)
```

### 2.3.4 启发式函数设计

构造启发式有四条主要路径。**松弛问题 (Relaxed Problem)** 放宽原问题的部分约束，其最优解代价天然是原问题的一个可纳启发式——例如八数码中允许方块忽略其他方块直接"跳"到目标位置，就得到曼哈顿距离启发式。**模式数据库 (Pattern Database)** 预先计算并存储子问题的解代价，再综合多个子问题得到可纳启发式。**支配关系 (Dominance)** 用于比较启发式：若对所有 `n` 有 $h₁(n) ≥ h₂(n)$，则称 $h₁$ **支配** $h₂$，被支配者信息量更小、导致扩展节点更多，故应优先选用更"紧"的 $h₁$。此外还可以**从经验中学习**，用大量训练实例拟合启发式的加权组合参数。

以八数码为例可以具体比较两个启发式。设目标状态与某当前状态如下（`_` 表示空格）：

```text
目标状态            当前状态
1 2 3               7 2 4
4 5 6               5 _ 6
7 8 _               8 3 1
```

**错位棋子数 (Misplaced Tiles)** $h₁$ 统计位置与目标不一致的棋子：`2`、`6` 已就位，其余 7 个棋子错位，故 $h₁ = 7$。**曼哈顿距离 (Manhattan Distance)** $h₂$ 累加每个棋子到目标位置的横向与纵向距离之和，逐棋子计算如下。

| 棋子 | 当前位置 | 目标位置 | 距离 |
|:---:|:---:|:---:|:---:|
| 7 | (0,0) | (2,0) | 2 |
| 4 | (0,2) | (1,0) | 3 |
| 5 | (1,0) | (1,1) | 1 |
| 8 | (2,0) | (2,1) | 1 |
| 3 | (2,1) | (0,2) | 3 |
| 1 | (2,2) | (0,0) | 4 |
| **合计** | | | **14** |

即 $h₂ = 14$。两者都可纳：$h₁$ 来自"棋子可无视其他棋子直接落入空位"的松弛，$h₂$ 来自"棋子可无视占用、逐格移动到目标"的松弛，移动步数都不会超过实际步数，故从不高估。更重要的是，$h₂$ **支配** $h₁$：每个错位棋子至少需移动 1 步，而曼哈顿距离正是该棋子的最少移动步数，逐棋子求和即得 $h₂(n) ≥ h₁(n)$ 对一切 `n` 成立，上例中 `14 > 7` 即为佐证。由于 $h₂$ 更紧，基于它的 A* 会扩展更少的节点。

## 2.4 局部搜索与最优化

**局部搜索 (Local Search)** 与经典搜索的根本区别是**不关心路径**，只关注最终状态（解的质量）。它适用于最优化问题——状态本身即解，无需记录从起点到达解的路径。把状态空间想象成地形，每个状态有一个**目标函数值**（高度），求解就是找到全局最高的峰（最大化）或最低的谷（最小化），这称为**状态空间地形图 (State Space Landscape)**。地形由位置（状态）、高度（目标函数值）与移动（邻域操作）三要素构成。局部搜索的典型困境是：它只沿邻域爬升，容易停在并非全局最优的位置。

### 2.4.1 爬山法

爬山法 (Hill Climbing) 从当前解出发，在邻域中选择使目标函数改进最大的状态，不断向上攀登直到无法改进，本质是**贪心局部搜索**。它有三种典型缺陷：**局部最优 (Local Maximum)** 指四周均更低但并非全局最高；**高原 (Plateau)** 指邻域内目标值相同、算法失去方向；**山脊 (Ridge)** 指单步邻域看似无法提升、却需连续多步才能到达更高峰。针对这些缺陷产生了若干变体。

| 变体 | 做法 | 特点 |
|:---|:---|:---|
| 随机爬山法 | 在更优邻居中随机选一个移动 | 不一定最优，收敛较慢 |
| 首选爬山法 | 一旦找到更优邻居即移动 | 生成邻居的开销较小 |
| 随机重启爬山法 | 多次从随机初值运行并取最优 | 次数足够时以概率 1 找到全局最优 |

前两种变体只是改变了在更优邻居间的选择方式，随机重启则是应对局部最优最直接有效的手段，在 NP 难问题中被广泛采用。

### 2.4.2 模拟退火

模拟退火 (Simulated Annealing, SA) 的灵感来自冶金中的金属退火：高温时原子剧烈随机运动（探索），缓慢降温后趋于低能量态（利用）。它在爬山法的基础上允许以一定概率接受更差的状态，接受概率由 Boltzmann 分布给出：$P(accept worse) = exp(-ΔE / T)$，其中 $ΔE$ 是目标值变差的程度，`T` 是当前温度，并随调度表 `schedule(t)` 逐步下降。高温阶段算法接近随机行走，实现全域探索；低温阶段则近似爬山，做局部精化。理论上只要降温足够慢，SA 以概率 1 找到全局最优。

### 2.4.3 束搜索

束搜索 (Beam Search) 在 BFS 的每一层只保留 `k` 个最有希望的节点继续扩展，`k` 称为**束宽**。它本质上是内存受限下的并行搜索，介于只保留最优 1 个的贪心与保留全部的穷举之间。束搜索广泛用于机器翻译、语音识别等序列生成任务，评分通常采用对数概率。

### 2.4.4 遗传算法概要

**遗传算法 (Genetic Algorithm, GA)** 与上述方法的分工值得单独说明。爬山法、模拟退火、束搜索都属于**单点或短记忆**的局部搜索，擅长在连续或结构化邻域中快速精化；GA 则维护一个**种群**，通过选择、交叉、变异在多个区域并行探索，更适合多峰、组合爆炸、约束复杂的优化问题。

GA 的灵感来自自然选择与遗传学，基本流程为：初始化种群（一组候选解）→ 评估适应度 → 选择父代 → 交叉产生子代 → 变异引入多样性 → 形成新一代 → 重复至收敛。其三个核心算子是：**选择 (Selection)** 按适应度挑选父代（轮盘赌、锦标赛等），**交叉 (Crossover)** 交换两父代的部分基因（单点、两点、均匀等），**变异 (Mutation)** 以小概率随机改变基因位以维持多样性。其理论依据是**模式定理 (Schema Theorem)**：适应度高、定义长度短、阶数低的模式在进化中以指数速率增长。本节仅作概念性速览，完整的算子设计、GA 变体与多目标进化算法见第 4 章 §4.1。

## 2.5 对抗搜索

对抗搜索 (Adversarial Search) 处理多智能体环境中**竞争性**的博弈场景。在**零和博弈**中，对手的目标与己方相反，任何一方的收益都来自另一方的损失，因此搜索时必须假设对手会做出最优应对。博弈问题可以用六要素形式化：**初始状态** $S₀$ 是棋盘初始布局；**玩家函数** `Player(s)` 返回当前轮到谁走；**动作集合** `Actions(s)` 是当前合法走法；**转移模型** `Result(s, a)` 给出走一步后的结果状态；**终局测试** `Terminal-test(s)` 判断游戏是否结束；**效用函数** `Utility(s, p)` 给出终局收益（如国际象棋赢 +1、输 −1、平 0）。

### 2.5.1 极小极大算法

极小极大算法 (Minimax) 的核心思想是：MAX 方（我方）试图最大化最终收益，MIN 方（对手）试图最小化，双方交替决策形成博弈树。设 `v(s)` 为状态 `s` 下 MAX 能得到的最佳收益，则递归定义为：若 `s` 为终局，`v(s) = Utility(s)`；若轮到 MAX，`v(s) = max_{a} v(Result(s, a))`；若轮到 MIN，`v(s) = min_{a} v(Result(s, a))`。若博弈树深度为 `d`、分支因子为 `b`，则时间 `O(b^d)`、空间 `O(bd)`（深度优先实现）。国际象棋中 $b ≈ 35$、$d ≈ 100$，穷举完全不可行。

```text
算法：极小极大搜索 (Minimax)
1.  function Minimax(state) -> 效用值:
2.      if Terminal-test(state): return Utility(state)
3.      if Player(state) == MAX:
4.          return max over a ∈ Actions(state) of Minimax(Result(state, a))
5.      else:  // MIN
6.          return min over a ∈ Actions(state) of Minimax(Result(state, a))
```

当博弈树无法搜到终局时，需要在深度限制处用**评估函数 (Evaluation Function)** `Eval(s)` 近似效用。好的评估函数应满足三点：对终局状态的排序与真实效用一致、计算足够快、能反映局面的关键特征。它通常取线性加权形式 $Eval(s) = w₁ f₁(s) + w₂ f₂(s) + … + wₙ fₙ(s)$，国际象棋常用特征包括子力（兵 1、马/象 3、车 5、后 9）、棋子位置、机动性与王的安全性。线性模型的局限在于难以刻画特征间的非线性相互作用，并且存在**地平线效应 (Horizon Effect)**——看似安全的走法把危机推迟到搜索深度之外，可用**静态搜索 (Quiescence Search)** 缓解。

### 2.5.2 Alpha-Beta 剪枝

Alpha-Beta 剪枝 (Alpha-Beta Pruning) 在 minimax 搜索中动态维护两个边界：$α$ 是 MAX 的当前最佳选择下界，$β$ 是 MIN 的当前最佳选择上界。当某条路径确定不可能改进当前已找到的最优值时即可剪枝：对 MAX 节点，若 $v ≥ β$ 则剪枝（β 剪枝），因为 MIN 不会允许这种情况；对 MIN 节点，若 $v ≤ α$ 则剪枝（α 剪枝），因为 MAX 不会选择这条路。

```text
算法：Alpha-Beta 剪枝
1.  function AlphaBeta(state, α, β) -> 效用值:
2.      if Terminal-test(state): return Utility(state)
3.      if Player(state) == MAX:
4.          v ← -∞
5.          for each a ∈ Actions(state):
6.              v ← max(v, AlphaBeta(Result(state, a), α, β))
7.              if v ≥ β: return v           // β 剪枝
8.              α ← max(α, v)
9.          return v
10.     else:  // MIN
11.         v ← +∞
12.         for each action ∈ Actions(state):
13.             v ← min(v, AlphaBeta(Result(state, a), α, β))
14.             if v ≤ α: return v           // α 剪枝
15.             β ← min(β, v)
16.         return v
```

剪枝的效率取决于节点排序。理想情况下，若每层的最佳走法总是最先被探索，根的第一个（最优）子节点完整展开后会为根确立很高的 $α$ 下界；此后根的其余每个 MIN 子节点只需考察其第一个（最好）孙子即可触发 α 剪枝，无需展开其余 `b-1` 个孙子。把这一模式逐层递归，每两层实际处理的节点数约为 `b` 而非 $b²$，即**有效分支因子从 `b` 降为 $√b$**，总节点数由 `b^d` 变为 $(√b)^d = b^{d/2}$（可证叶节点数约为 `b^{⌈d/2⌉} + b^{⌊d/2⌋} - 1`）。这等价于相同时间预算下**前瞻深度翻倍**。实践中，吃子优先、杀王优先等启发式排序可使剪枝接近理论最优。

一个具体数值例子能说明剪枝过程。设根为 MAX，三个 MIN 子节点 `B、C、D`，叶节点效用如下：

```text
                 MAX
        ┌─────────┼─────────┐
        B         C         D      (MIN)
      ┌─┴─┐    ┌─┴─┐    ┌─┼─┐
      5   6    4   3    7 2 9     (叶)
```

Minimax 的值为 `B = min(5,6) = 5`，`C = min(4,3) = 3`，`D = min(7,2,9) = 2`，根为 `max(5,3,2) = 5`。Alpha-Beta 从 $α=-∞, β=+∞$ 起步：展开 `B` 的两个叶子后根得 $α = 5$；展开 `C` 时读到叶 4 使 `C` 的 $β = 4$，此时 $v = 4 ≤ α = 5$ 触发 α 剪枝，叶 3 无需访问；展开 `D` 时读到叶 7 不剪枝，读到叶 2 使 $v = 2 ≤ α = 5$ 再次触发 α 剪枝，叶 9 无需访问。最终仅评估 5 个叶节点，跳过了 2 个，剪掉的正是那些不影响最终决策的子树。

### 2.5.3 蒙特卡洛树搜索

传统 Minimax（含 Alpha-Beta）依赖评估函数与深度限制，在围棋这类大分支因子的游戏中力不从心（$b ≈ 250$）。**蒙特卡洛树搜索 (Monte Carlo Tree Search, MCTS)** 另辟蹊径，不做穷举搜索，而是通过**随机模拟 (Playout / Rollout)** 估计胜率。它的核心是如下四步循环。

- **选择 (Selection)**：从根节点出发，依据树策略（如 UCB1）选择最有价值的子节点，直到到达未完全展开的节点；
- **扩展 (Expansion)**：若该叶节点不是终局，为它添加一个或多个子节点；
- **模拟 (Simulation)**：从新节点出发执行随机走子（或轻量级策略）直至终局，得到胜负结果；
- **反向传播 (Backpropagation)**：将结果沿路径向上更新各节点的访问次数与胜率统计。

选择步骤中的 **UCB1 公式**平衡了利用与探索：$UCT(j) = wⱼ / nⱼ + C · √(ln N / nⱼ)$，其中 $wⱼ$ 是节点 `j` 的获胜次数，$nⱼ$ 是其访问次数，`N` 是父节点访问次数，`C` 是探索常数；前半项偏向高胜率节点（利用），后半项偏向访问不足的节点（探索）。

```text
算法：蒙特卡洛树搜索 (MCTS) —— 四步循环
1.  root ← 以当前局面建立根节点
2.  while 时间预算未耗尽:
3.      node ← 从 root 出发按 UCT 反复选择子节点，直到未完全展开节点   // 选择
4.      if node 不是终局: node ← 为其添加一个未尝试动作的新子节点    // 扩展
5.      result ← 从 node 起随机走子（或轻量策略）直至终局             // 模拟
6.      沿 node → root 路径: n ← n + 1，w ← w + result            // 反向传播
7.  return root 下访问次数 n 最大的子节点对应的动作
```

**AlphaGo / AlphaZero** 在 MCTS 框架中嵌入深度神经网络：策略网络指导选择与扩展，替代随机走子；价值网络评估局面，替代随机模拟，从而达到了超越人类世界冠军的水平。AlphaZero 进一步移除了对人类棋谱的依赖，完全通过自对弈学习。

## 2.6 约束满足问题 (CSP)

**约束满足问题 (Constraint Satisfaction Problem, CSP)** 把状态表示为一组**变量**及其**值域**之间的**约束**。与经典搜索不同，它的目标不是找到一条到达目标状态的路径，而是找到一组满足所有约束的变量赋值。CSP 表示力强，可自然建模调度、配置、排课、地图着色等大量实际问题。它由三个要素构成：**变量集合** $X = {X₁, …, Xₙ}$ 是待赋值的实体；**值域集合** $D = {D₁, …, Dₙ}$ 给出每个变量的取值范围（CSP 通常处理有限离散值域）；**约束集合** $C = {C₁, …, Cₘ}$ 规定赋值之间的合法组合，按其涉及的变量数可分为**一元约束**、**二元约束**（如 $Xᵢ ≠ Xⱼ$）与**全局约束**（如 `AllDiff`）。

CSP 有一个重要特性：**赋值是可交换的**。先给 A 赋值再给 B 赋值，与相反顺序结果相同，因此搜索无需考虑路径，只要按变量顺序依次赋值即可，空间从 $O(n! · dⁿ)$ 缩小为 $O(dⁿ)$。其基本算法是**回溯搜索 (Backtracking Search)**，本质是带剪枝的深度优先搜索：每次选择一个未赋值变量，尝试其值域中的每个值，一旦与约束冲突就回溯。CSP 中的"状态"是部分赋值，目标测试是所有变量均已赋值且约束全部成立。

### 2.6.1 实例：地图着色与任务调度

**地图着色 (Map Coloring)** 是用有限种颜色为每个区域着色，使相邻区域颜色不同。以澳大利亚为例，变量为 `{WA, NT, SA, Q, NSW, V, T}`，值域均为 `{红, 绿, 蓝}`，二元约束为相邻区域颜色不等，即 $WA ≠ NT, WA ≠ SA, NT ≠ SA, NT ≠ Q, SA ≠ Q, SA ≠ NSW, SA ≠ V, Q ≠ NSW, NSW ≠ V$（T 与大陆隔离，可单独处理）。该问题有解，例如 `WA=红, NT=绿, SA=蓝, Q=红, NSW=绿, V=红, T=红`。

**任务调度 (Job Scheduling)** 可看作同类问题。设有课程 `A、B、C、D`，每门课有可选时间段，约束包括"同一教师的两门课不能同时段""同一教室同一时段只能排一门课""先修课需排在后续课程之前"等，用二元约束 `C(X, Y)` 表示"`X` 的时段必须早于 `Y`"即可统一求解。

回溯搜索的直观轨迹如下：按 $WA → NT → SA → Q → NSW → V$ 的顺序、采用最早可用值，依次得 `WA = 红`，`NT = 绿`（避开红），`SA = 蓝`（避开红、绿），`Q = 红`（避开绿、蓝），`NSW = 绿`（避开红、蓝），`V = 红`（避开蓝、绿），一次成功。若中途某变量值域为空，则回溯到最近的可改选择点。其规范形式如下。

```text
算法：CSP 回溯搜索
1.  function Backtrack(assignment):
2.      if assignment 已为所有变量赋值: return assignment
3.      var ← Select-Unassigned-Variable(csp, assignment)    // 如 MRV
4.      for each value ∈ Order-Domain-Values(var, assignment): // 如 LCV
5.          if value 与 assignment 一致:
6.              assignment ← assignment ∪ {var = value}
7.              inferences ← Inference(csp, var, value)      // 如 FC / AC-3
8.              if inferences ≠ failure:
9.                  result ← Backtrack(assignment ∪ inferences)
10.                 if result ≠ failure: return result
11.             assignment ← assignment \ {var = value}       // 撤销赋值
12.     return failure
```

### 2.6.2 约束传播：前向检验与弧相容

**约束传播 (Constraint Propagation)** 的核心思想是在搜索过程中（甚至搜索前）利用约束缩小变量值域，提前排除不可能的值。最基本的做法是**前向检验 (Forward Checking, FC)**：为某变量赋值后，立即检查所有尚未赋值的邻居，删除与其冲突的值，若某变量值域因此变空就立即回溯——它是回溯搜索最常见的第一道防线。

**弧相容 (Arc Consistency, AC)** 传播得更远。对二元约束 `C(X, Y)`，称弧 $X → Y$ 是弧相容的，当且仅当对 `X` 值域中的每个值，`Y` 的值域中都存在至少一个值使 `C` 成立。由于它同时考虑非直接邻居，比前向检验缩窄得更彻底。**AC-3 算法**是最广泛使用的弧相容算法：将所有弧放入队列，依次检查每条弧，若不相容则删除相应值并把受影响的弧重新入列，直到队列为空；其复杂度为 $O(cd³)$（`c` 为约束数，`d` 为最大值域大小）。

```text
算法：AC-3 弧相容
1.  queue ← 所有弧 (Xi, Xj) 的集合
2.  while queue 非空:
3.      (Xi, Xj) ← queue.pop()
4.      if Revise(csp, Xi, Xj):            // D(Xi) 有删减则返回 true
5.          if D(Xi) == ∅: return false    // 值域为空，CSP 无解
6.          for each Xk ∈ neighbors(Xi) \ {Xj}:
7.              queue.push((Xk, Xi))        // 重新检查指向 Xi 的弧
8.  return true

function Revise(csp, Xi, Xj):
1.  revised ← false
2.  for each x ∈ D(Xi):
3.      if 不存在 y ∈ D(Xj) 使 C(Xi, Xj) 成立:
4.          D(Xi) ← D(Xi) \ {x}
5.          revised ← true
6.  return revised
```

以变量 `X、Y、Z`（值域 `D(X)={1,2}`、`D(Y)={1,2}`、`D(Z)={1,2,3}`，约束为 $X ≠ Y$ 与 `Y < Z`）为例：检查 `(X,Y)`、`(Y,X)`、`(Y,Z)` 均无删减；检查 `(Z,Y)` 时发现 `z=1` 没有任何 `y < 1`，于是删去 1，`D(Z)` 变为 `{2,3}`，并把 `(Y,Z)` 重新入列；再次检查 `(Y,Z)` 仍然相容；队列清空后检查结束。弧相容提前排除了 `Z=1`，从而缩小了后续搜索空间；若某步骤值域变空，则说明该 CSP 无解，可立即失败。相容性还可推广为 **k-相容性 (k-Consistency)**：1-相容即节点相容（每个值满足一元约束），2-相容即弧相容，强 k-相容要求对所有 $i ≤ k$ 均为 i-相容。更强的传播能进一步缩窄搜索空间，但计算代价也相应增大。

### 2.6.3 变量与值的选择启发式

回溯搜索的效率高度依赖变量与值的选取顺序，常用三条启发式。**最小剩余值 (Minimum Remaining Values, MRV)** 选择当前值域最小的变量，即最可能受限者优先（"最易失败的先处理"）；**度启发式 (Degree Heuristic)** 在 MRV 平局时选择与其他未赋值变量约束最多者，即影响力最大者优先；**最少约束值 (Least Constraining Value, LCV)** 在赋值时选择给邻居变量留下最大选择余地者，即"留有余地"的值优先。前者用于选变量，后者用于选值，两者配合可显著减少回溯。

此外还有两类智能回溯改进。**回跳 (Backjumping)** 在变量值域全部尝试失败后，不是简单退回上一层，而是依据冲突集分析跳回导致冲突的根源变量；**学习 (Learning)** 则把导致失败的赋值组合记录为新约束，称为**诺戈德 (NoGood)**，以避免将来重复尝试同样的组合。

## 2.7 本章小结

**核心要点回顾**

| 主题 | 要点 |
|:---|:---|
| **问题形式化** | 搜索问题由初始状态、动作、转移模型、目标测试、路径代价五要素刻画；状态空间图是问题固有的，搜索树由算法动态构建，同一状态可在树中重复出现 |
| **无信息搜索** | BFS 用 FIFO 队列、等代价下最优但空间 `O(b^d)`；DFS 用 LIFO 栈、省内存但不完备非最优；DLS/IDS 兼顾完备与省内存；UCS 用优先队列按 `g` 扩展，完备且最优 |
| **有信息搜索** | 贪心只看 `h`；A* 用 `f = g + h`，`h` 可纳则最优、`h` 一致则每节点最多扩展一次且顺序最优；A* 在其启发式下最优效率最高；IDA* 用阈值迭代把空间降到 `O(bd)` |
| **启发式设计** | 松弛问题、模式数据库、支配关系、经验学习是四条主要路径；八数码中曼哈顿距离支配错位棋子数 |
| **局部搜索** | 爬山法易陷局部最优、高原、山脊，随机重启与模拟退火可缓解；束搜索在内存受限下折中；遗传算法属种群进化方法（见第 4 章 §4.1） |
| **对抗搜索** | Minimax 递归 max/min，Alpha-Beta 用 $α/β$ 剪枝把复杂度降到 `O(b^{d/2})`，评估函数与节点排序决定实战效果；MCTS 以选择-扩展-模拟-反向传播四步循环估计胜率，AlphaGo/AlphaZero 将其与深度网络结合 |
| **CSP** | 以变量、值域、约束建模；回溯搜索 + MRV/度启发式/LCV + 前向检验 + AC-3 弧相容是最常用组合；AC-3 反复修订弧直至队列为空，可提前发现无解 |
