## 2. 问题求解与搜索策略

**本章导读**：搜索是人工智能中最基础的求解范式之一——无论是下棋、规划路径，还是为变量赋值以满足约束，本质上都可转化为在状态空间中寻找从初始状态到目标的路径或最优解。本章先给出问题的形式化框架与搜索算法性能的度量标准，随后依次介绍无信息搜索、有信息（启发式）搜索、局部搜索、对抗搜索与约束满足问题六大类方法。读完本章，你应能针对具体问题选择合适的搜索策略，并说清其完备性、最优性与复杂度边界。

**学习目标**：
完成本章的学习后，你应当能够：
- 用初始状态、动作、转移模型、目标测试、路径代价五要素形式化一个实际问题，并区分状态空间图与搜索树；
- 说明 BFS、DFS、DLS、IDS、UCS 的数据结构、扩展顺序及完备性/最优性，并推导其时间与空间复杂度；
- 设计满足可纳性与一致性的启发式函数，运用 A*、IDA* 求解最优路径，并解释 A* 的"最优效率"含义；
- 描述爬山法、模拟退火、束搜索的机制与适用场景，并说明局部搜索与遗传算法的分工（后者详见第 4 章 §4.1）；
- 运用 Minimax 与 Alpha-Beta 剪枝分析零和博弈，理解评估函数设计与 MCTS 的四步循环；
- 将问题建模为 CSP，应用回溯搜索、前向检验与 AC-3 弧相容进行求解；
- 针对同一问题比较不同搜索策略在时间、空间、最优性上的权衡。

### 2.1 问题形式化：状态空间图、问题的形式化表示

- **问题形式化的五要素**：一个问题可以用五个要素形式化定义——
    - ① **初始状态 (Initial State)**：智能体出发时所在的状态；
    - ② **动作 (Actions)**：在每个状态 `s` 下可执行的动作集合 `ACTIONS(s)`；
    - ③ **转移模型 (Transition Model)**：执行动作 `a` 后从状态 `s` 转移到后继状态 `s'` 的描述，即 `RESULT(s, a) = s'`，也称为**后继函数**；
    - ④ **目标测试 (Goal Test)**：判断当前状态是否为目标状态（可以是显式状态集合或隐式条件判断）；
    - ⑤ **路径代价函数 (Path Cost Function)**：为每条路径分配一个数值代价，通常为各步代价之和 `g(path) = Σ cost(s_i, a_i, s_{i+1})`，求解目标是找到总代价最小的解。

- **状态空间图 (State Space Graph)**：将问题空间中所有可能状态及其转移关系抽象为图结构——节点表示状态，有向边表示动作——该图在搜索前即已隐含存在，实际的搜索过程是在图上探寻路径。
- **搜索树 (Search Tree)**：从初始状态出发，依据动作展开后继节点所形成的树结构。搜索树在探索过程中逐步构建，其节点可能对应相同的状态（状态重复），状态空间图是唯一的，而搜索树依赖于搜索策略。

> 状态空间图是问题固有的结构，搜索树则是算法在探索过程中逐步构建的。在 Romania 地图上，Arad 可能经不同路径（如 Arad → Sibiu → Arad、Arad → Zerind → Oradea → Sibiu → Arad）多次进入搜索树，因此树搜索必须依靠**重复状态检测**或**闭环检测**来避免无限循环与冗余扩展。

- **良好定义的问题**：当一个问题的初始状态、动作集合、转移模型、目标测试和路径代价函数均被明确指定时，称为**良定义问题 (Well-Defined Problem)**。解决方案是从初始状态到目标状态的一组动作序列。
- **抽象 (Abstraction)**：问题形式化的关键在于去除与现实无关的细节，保留对求解有影响的核心要素——这是简化复杂现实、使搜索可行的关键步骤。一个好的抽象层次应满足：被移除的细节不影响解的合法性，且抽象后得到的动作应易于执行。
- **经典示例**：
    - *八数码问题*：状态为 3×3 棋盘上 8 个数字方块与一个空格的排列，动作为空格上下左右移动，目标为棋子的特定排列；
    - *真空吸尘器世界*：两个房间、吸尘器位置与房间清洁状态的组合构成状态空间；
    - *路径规划问题*：状态为地图上的位置，动作为移动到相邻城市，路径代价为距离。

- **问题求解性能的度量**：
    - **完备性 (Completeness)**：如果有解，算法是否保证找到解？
    - **最优性 (Optimality)**：找到的解是否代价最小？
    - **时间复杂度 (Time Complexity)**：搜索所需时间（通常以搜索过程中产生的节点数衡量）；
    - **空间复杂度 (Space Complexity)**：算法运行所需的最大内存。
- **搜索策略分类**：
    - **无信息搜索 (Uninformed/Blind Search)**：仅使用问题定义本身的信息，不借助额外领域知识；
    - **有信息搜索 (Informed/Heuristic Search)**：利用启发式函数评估节点到目标的距离，选择更有希望的路径。

### 2.2 无信息搜索：广度优先、深度优先、一致代价搜索

- **无信息搜索 (Uninformed Search)** 又称为**盲目搜索 (Blind Search)**，只使用问题定义中可用的信息，不借助任何外部领域知识。搜索策略仅依赖于已扩展节点的顺序，而无信息搜索的核心区别在于使用何种数据结构（队列 vs 栈 vs 优先队列）来维护**边缘节点 (Frontier / Fringe)**。

#### 2.2.2 广度优先搜索 (BFS)

- **核心思想**：先扩展根节点，再扩展根节点的所有后继，依此类推，逐层推进。使用 **FIFO 队列** 作为边缘；
- **节点生成顺序**：从浅到深，从深度的第 `d` 层依次展开至第 `d+1` 层；
- **算法复杂度**：时间 `O(b^d)`，空间 `O(b^d)`——对浅层问题可行，对大深度问题内存爆炸；
- **性质**：完备（若 `b` 有限且路径深度有限），**等代价下最优**（step cost 相同时），不等代价时不一定最优。

```text
算法：广度优先搜索 (BFS)
──────────────────────────────────────────────
输入：problem —— 含 initial、goal_test、actions、result
输出：解路径，或 failure

1.  node ← 节点(initial, parent = null, path_cost = 0)
2.  if problem.goal_test(node.state): return 解路径
3.  frontier ← 队列([node])            // FIFO，队首出、队尾入
4.  explored ← ∅                       // 已扩展状态集合
5.  while frontier 非空:
6.      node ← frontier.pop()          // 取队首
7.      explored ← explored ∪ {node.state}
8.      for each action ∈ problem.actions(node.state):
9.          child ← 子节点(node, action)
10.         if child.state ∉ explored ∪ frontier:
11.             if problem.goal_test(child.state): return 解路径   // 生成时检测
12.             frontier.push(child)     // 入队尾
13. return failure
```

#### 2.2.3 深度优先搜索 (DFS)

- **核心思想**：每步优先扩展当前搜索树中最深的节点，一路到底再回溯。使用 **LIFO 栈**（或递归调用）；
- **算法复杂度**：时间 `O(b^m)`（`m` 为最大深度），空间 `O(bm)`——内存优势显著，仅需存储一条路径；
- **性质**：**不完备**——无限深分支会导致陷入死循环（可通过深度限制避免）；**非最优**。

```text
算法：深度优先搜索 (DFS)
──────────────────────────────────────────────
输入 / 输出同 BFS

1.  frontier ← 栈([节点(initial, parent = null, path_cost = 0)])   // LIFO
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()            // 取栈顶，即当前最深节点
5.      if problem.goal_test(node.state): return 解路径            // 出栈时检测
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored:
10.             frontier.push(child)
11. return failure
```

**Romania 实例 DFS 轨迹**（邻居按 Timisoara、Sibiu、Zerind 的顺序压栈，使 Zerind 位于栈顶）：

| 3 | Oradea | Sibiu | Timisoara, Sibiu(Arad), Sibiu(Oradea) | **Sibiu 重复入栈** |
| 4 | Sibiu | Fagaras, Rimnicu（Arad、Oradea 已见） | Timisoara, Sibiu(Arad), Rimnicu, Fagaras | |

DFS 找到的路径 `Arad → Zerind → Oradea → Sibiu → Fagaras → Bucharest` 代价 `75 + 71 + 151 + 99 + 211 = 607`，远非最优。此例还直观展示了搜索树中的**重复状态**：Sibiu 同时以不同父节点入栈，说明搜索树并不等同于状态空间图。

#### 2.2.4 深度限制搜索 (DLS) 与迭代加深搜索 (IDS)

- **深度限制搜索 (DLS)**：为 DFS 设置最大深度 `ℓ`，解决了无限深路径问题，但若目标深度超过 `ℓ` 则可能漏解，故不完备；
- **迭代加深搜索 (IDS)**：将 DLS 与 BFS 结合——逐步增大深度限制，每次从初始状态重新搜索。兼具 BFS 的完备性与 DFS 的空间效率，时间 `O(b^d)`，空间 `O(bd)`。

```text
算法：深度限制搜索 (DLS)
──────────────────────────────────────────────
1.  function DLS(node, limit):
2.      if problem.goal_test(node.state): return 解路径
3.      if limit == 0: return cutoff
4.      cutoff_occurred ← false
5.      for each action ∈ problem.actions(node.state):
6.          child ← 子节点(node, action)
7.          result ← DLS(child, limit - 1)
8.          if result == 解路径: return result
9.          if result == cutoff: cutoff_occurred ← true
10.     return cutoff if cutoff_occurred else failure

算法：迭代加深搜索 (IDS)
──────────────────────────────────────────────
1.  for depth ← 0, 1, 2, … ∞:
2.      result ← DLS(节点(initial), depth)
3.      if result ≠ cutoff: return result     // 找到解，或确定无解
```

- **复杂度推导：为什么 IDS 时间仍是 `O(b^d)`？**
IDS 反复重搜浅层，看似浪费：当深度限制为 `i` 时，DLS 生成的节点数为 `1 + b + b² + … + b^i`。累加所有轮次：

`Σ_{i=0}^{d} (b^{i+1} - 1)/(b - 1) = (b^{d+1} - 1)/(b - 1) - (d + 1) ≈ b^d · (b/(b-1))`

对于 `b ≥ 2`，放大因子 `b/(b-1) ≤ 2`，是常数而非 `d` 的因子。也就是说**绝大部分开销集中在最后一轮（深度 `d`）**，前 `d-1` 轮的总和只有最后一轮的一个常数倍。因此总时间仍是 `O(b^d)`，仅比 BFS 多一个常数倍，却把空间从 `O(b^d)` 降到 `O(bd)`——这是 IDS 最核心的卖点。

#### 2.2.5 一致代价搜索 (UCS)

- **核心思想**：优先扩展**路径代价 `g(n)` 最小**的节点，使用**优先队列**（如最小堆）管理边缘；
- **本质**：UCS 是 BFS 在不等代价下的推广——当每步代价相等时，UCS 退化为 BFS；
- **性质**：完备且最优（只要每步代价 > 0），时间和空间均为 `O(b^{1+⌊C*/ε⌋})`，其中 `C*` 为最优解的代价，`ε` 为最小步代价。

```text
算法：一致代价搜索 (UCS)
──────────────────────────────────────────────
1.  frontier ← 优先队列([节点(initial, path_cost = 0)])   // 按 g 升序
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()               // g 最小的节点
5.      if problem.goal_test(node.state): return 解路径     // 出队时检测
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored:
10.             if child.state ∈ frontier 且已有 g 更小:
11.                 continue                // 已有更优路径，跳过
12.             else if child.state ∈ frontier:
13.                 frontier.replace(child) // 发现更优路径，更新
14.             else:
15.                 frontier.push(child)
16. return failure
```

- **无信息搜索总结（设分支因子 `b`，最浅目标深度 `d`，最大深度 `m`）**：

| 算法 | 完备性 | 最优性 | 时间复杂度 | 空间复杂度 |
|:---|:---:|:---:|:---|:---|
| BFS | ✅ | 等代价下 ✅ | `O(b^d)` | `O(b^d)` |
| DFS | ❌ | ❌ | `O(b^m)` | `O(bm)` |
| DLS | ❌ | ❌ | `O(b^ℓ)` | `O(bℓ)` |
| IDS | ✅ | 等代价下 ✅ | `O(b^d)` | `O(bd)` |
| UCS | ✅ | ✅ | `O(b^{1+⌊C*/ε⌋})` | 同时间 |

### 2.3 有信息（启发式）搜索：贪心最优搜索、A* 算法、IDA*、启发式函数设计

- **有信息搜索 (Informed Search)** 使用**领域知识**指导搜索方向，该知识通过**启发式函数 (Heuristic Function)** `h(n)` 编码——`h(n)` 估计从节点 `n` 到目标状态的最小代价。

#### 2.3.1 贪心最优搜索 (Greedy Best-First Search)

- **策略**：始终扩展 `h(n)` 最小的节点——即"看起来离目标最近的节点"；
- **类比**：类似 DFS 以"离目标远近"为向导，总是朝着最有希望的方向前进；
- **性质**：不完备（可能陷入死循环），不最优，但通常搜索速度极快；
- **复杂度**：最坏情况 `O(b^m)`，但好的启发式函数可使其接近线性。

```text
算法：贪心最优优先搜索 (Greedy Best-First Search)
──────────────────────────────────────────────
1.  frontier ← 优先队列([节点(initial)])       // 按 h 升序
2.  explored ← ∅
3.  while frontier 非空:
4.      node ← frontier.pop()                  // h 最小的节点
5.      if problem.goal_test(node.state): return 解路径
6.      explored ← explored ∪ {node.state}
7.      for each action ∈ problem.actions(node.state):
8.          child ← 子节点(node, action)
9.          if child.state ∉ explored ∪ frontier:
10.             frontier.push(child)
11. return failure
```

#### 2.3.2 A* 搜索 (A-Star Search)

- **评价函数**：`f(n) = g(n) + h(n)`，其中：
    - `g(n)`：从初始状态到节点 `n` 的实际路径代价（已知）；
    - `h(n)`：从节点 `n` 到目标的估计代价（启发式）；
    - `f(n)`：经过节点 `n` 的完整路径的估计总代价。
- **核心机制**：A* 在 UCS（只考虑已付出的代价 `g(n)`）与贪心搜索（只看剩余估计 `h(n)`）之间取得平衡——`g(n)` 可看作"回望过去"，`h(n)` 可看作"展望未来"；
- **可纳性 (Admissibility)**：`h(n)` 永不高估从 `n` 到目标的实际代价，即对所有节点 `n` 有 `h(n) ≤ h*(n)`（`h*` 为真实最优代价）。当 `h` 可纳时，A* 在图搜索（需配合**闭环检测**）下是**最优的**；
- **一致性 / 单调性 (Consistency / Monotonicity)**：对每条边 `(n, a, n')`，满足 `h(n) ≤ c(n, a, n') + h(n')`。一致性是可纳性的更强条件，同时也是三角形不等式的体现。一致启发式保证 A* 在图搜索下以最优顺序扩展节点，且每个节点最多扩展一次；
- **性质总结**：A* 是完备的，在 `h` 可纳时最优，在 `h` 一致时最优效率最高（在同等信息条件下，所有最优搜索中 A* 扩展的节点最少）。

```text
算法：A* 图搜索 (A-Star Graph Search，带 closed 集)
──────────────────────────────────────────────
1.  frontier ← 优先队列([节点(initial, g = 0, f = h(initial))])  // 按 f 升序
2.  closed ← ∅                                  // 已扩展状态
3.  while frontier 非空:
4.      node ← frontier.pop()                     // f 最小的节点
5.      if problem.goal_test(node.state): return 解路径
6.      if node.state ∈ closed: continue          // 丢弃重复或过期节点
7.      closed ← closed ∪ {node.state}
8.      for each action ∈ problem.actions(node.state):
9.          child ← 子节点(node, action)           // 计算 g、f = g + h
10.         if child.state ∈ closed: continue
11.         if child.state ∈ frontier 且已有 g 更小:
12.             continue                           // frontier 中已有更优版本
13.         else if child.state ∈ frontier:
14.             frontier.replace(child)            // 发现更优 g，更新
15.         else:
16.             frontier.push(child)               // 首次到达，入队
17. return failure
```

**A* 的最优效率（optimally efficient）**：在启发式 `h` 相同的条件下，不存在另一个最优算法能保证扩展比 A* 更少的节点。理由如下：设 `C*` 为最优解代价，任取一个在最优路径上且 `f(n) = g(n) + h(n) < C*` 的节点 `n`。由于 `h` 可纳，经过 `n` 的解其真实代价不可能小于 `C*`；但 `n` 仍可能位于某条不劣于现有最优解的路径上——**要保证最优性就不能排除 `n` 所在的子树，因此必须扩展 `n`**。A* 恰好扩展了所有 `f(n) < C*` 的节点（以及部分 `f(n) = C*` 的节点），故已扩展到"保证最优所必需"的极限。需要强调：最优效率是相对于**给定启发式**而言的，换用信息量更大的启发式仍可减少扩展。

**Romania 实例 A* 轨迹**（`f = g + h_SLD`）：

| 步骤 | 扩展节点 (g, h, f) | 生成/更新 (g, f) | Frontier（按 f 升序） |
|:---:|:---|:---|:---|
| 1 | Arad (0, 366, 366) | Zerind(75, 449), Timisoara(118, 447), Sibiu(140, 393) | Sibiu393, Timisoara447, Zerind449 |
| 2 | Sibiu (140, 253, 393) | Rimnicu(220, 413), Fagaras(239, 415), Oradea(291, 671) | Rimnicu413, Fagaras415, Timisoara447, Zerind449, Oradea671 |
| 3 | Rimnicu (220, 193, 413) | Pitesti(317, 417), Craiova(366, 526) | Fagaras415, Pitesti417, Timisoara447, Zerind449, Craiova526, Oradea671 |
| 4 | Fagaras (239, 176, 415) | Bucharest(450, 450) | Pitesti417, Timisoara447, Zerind449, Bucharest450, Craiova526, Oradea671 |
| 5 | Pitesti (317, 100, 417) | Bucharest(418, 418) 更新 | **Bucharest418**, Timisoara447, Zerind449, Craiova526, Oradea671 |
| 6 | Bucharest (418, 0, 418) | 目标检出 | — |

A* 仅扩展了 6 个节点（Arad、Sibiu、Rimnicu、Fagaras、Pitesti、Bucharest）即锁定最优解 418，而 UCS 扩展了 12 个节点——启发式的信息量直接转化为搜索效率。注意 A* 在第 4 步先用 Fagaras 得到 450，随后靠 Pitesti 的 418 覆盖，与 UCS 类似，目标必须在**出队时**检测。

#### 2.3.3 迭代加深 A* (IDA\*)

- **动机**：A* 在大状态空间中内存开销极大（需存储所有已生成节点），IDA* 用迭代加深的方式规避内存问题；
- **做法**：每一轮设一个 `f` 值的阈值 `cutoff`，DFS 过程中若当前节点的 `f(n) > cutoff` 则剪枝并记录所有被剪节点的 `f` 值中的最小者作为下一轮的 cutoff；
- **性质**：保留 A* 的完备性与最优性，空间复杂度降为 `O(bd)`，在实际求解八数码等问题中广泛使用。

```text
算法：迭代加深 A* (IDA*)
──────────────────────────────────────────────
1.  threshold ← h(initial)
2.  loop:
3.      result, next_threshold ← DFS-F(节点(initial), g = 0, threshold)
4.      if result == 解路径: return result
5.      if next_threshold == ∞: return failure
6.      threshold ← next_threshold

function DFS-F(node, g, threshold):
1.  f ← g + h(node.state)
2.  if f > threshold: return (failure, f)        // 剪枝，并记录候选阈值
3.  if problem.goal_test(node.state): return (解路径, —)
4.  min_overflow ← ∞
5.  for each action ∈ problem.actions(node.state):
6.      child ← 子节点(node, action)
7.      result, t ← DFS-F(child, g + cost(action), threshold)
8.      if result == 解路径: return (解路径, —)
9.      min_overflow ← min(min_overflow, t)
10. return (failure, min_overflow)              // 下一轮阈值只升到最小的越界 f
```

#### 2.3.4 启发式函数设计方法

- **松弛问题 (Relaxed Problem)**：放宽原问题的某些约束后获得的问题。松弛问题的最优解代价是原问题的一个可纳启发式。例如八数码问题中，若允许方块直接"跳"到目标位置（忽略其他方块），即为曼哈顿距离启发式；
- **模式数据库 (Pattern Database)**：将子问题的解代价预先计算并存储，综合多个子问题得到可纳启发式；
- **支配关系 (Dominance)**：若对所有节点 `n` 均有 `h₁(n) ≥ h₂(n)`，则称 `h₁` **支配** `h₂`。被支配的启发式会被优先使用——因为它更"紧"（信息量更大），搜索效率更高；
- **从经验中学习**：通过求解大量训练实例，学习启发式函数的加权组合参数。

**八数码实例：曼哈顿距离 `h₂` 支配错位棋子数 `h₁`**

设目标状态与某中间状态如下（`_` 表示空格）：

```text
目标状态            当前状态
1 2 3               7 2 4
4 5 6               5 _ 6
7 8 _               8 3 1
```

- **错位棋子数 `h₁` (Misplaced Tiles)**：统计位置与目标不一致的棋子个数。`2`、`6` 已在正确位置，其余 7 个棋子错位，`h₁ = 7`；
- **曼哈顿距离 `h₂` (Manhattan Distance)**：每个棋子到目标位置的横向与纵向距离之和：

| 棋子 | 当前位置 | 目标位置 | 距离 |
|:---:|:---:|:---:|:---:|
| 7 | (0,0) | (2,0) | 2 |
| 4 | (0,2) | (1,0) | 3 |
| 5 | (1,0) | (1,1) | 1 |
| 8 | (2,0) | (2,1) | 1 |
| 3 | (2,1) | (0,2) | 3 |
| 1 | (2,2) | (0,0) | 4 |
| **合计** | | | **14** |

即 `h₂ = 14`。

- **两者均是可纳的**：`h₁` 来自"棋子可无视其他棋子直接落到任意空位"的松弛；`h₂` 来自"棋子可无视占用、逐格移动到目标"的松弛，移动步数不会超过实际步数，故永不高估；
- **曼哈顿距离支配错位棋子数**：每个错位的棋子至少需移动 1 步，而曼哈顿距离正是该棋子的**最少**移动步数，逐棋子求和即得 `h₂(n) ≥ h₁(n)` 对一切 `n` 成立。上例中 `14 > 7` 即为佐证。由于 `h₂` 更紧，基于 `h₂` 的 A* 扩展节点更少。

### 2.4 局部搜索与最优化：爬山法、模拟退火、束搜索、遗传算法

- **局部搜索 (Local Search)** 与经典搜索的根本区别在于**不关心路径**，只关注最终状态（解的质量）——适用于最优化问题，其中状态本身即解，不记录从起点到达解的路径。
- **状态空间地形图 (State Space Landscape)**：将状态空间视为地形——每个状态有一个**目标函数值**（高度），我们的目标是找到全局最高峰（最大化）或最低谷（最小化）。地形图由三要素组成：位置（状态）、高度（目标函数值）、移动（邻域操作）。
- **爬山法 (Hill Climbing)**：
    - **基本思路**：从当前解出发，在邻域中选择使目标函数改进最大的状态，不断向上攀登，直到无法改进为止——即**贪心局部搜索**；
    - **致命缺陷**：
        - **局部最优 (Local Maximum)**：四周均更低，但并非全局最高；
        - **高原 (Plateau)**：邻域中所有状态目标值相同，算法失去方向；
        - **山脊 (Ridge)**：单步邻域看似无法提升，但连续多步可达更高峰；
    - **改进变体**：
        - **随机爬山法 (Stochastic HC)**：随机选择邻域中任一优于当前的状态，而非最优；
        - **随机重启爬山法 (Random-Restart HC)**：多次从随机初始状态运行，取最优结果——在 NP 难问题中，执行足够多次后以概率 1 找到全局最优；
        - **首选爬山法 (First-Choice HC)**：依次生成邻居，一旦找到更优状态即移动。
- **模拟退火 (Simulated Annealing, SA)**：
    - **灵感来源**：冶金学中金属退火——高温时原子剧烈随机运动（探索），缓慢降温后趋于低能量态（利用）；
    - **核心机制**：允许以一定概率接受更差的状态，概率由 Boltzmann 分布给出：
        - `P(accept worse) = exp(-ΔE / T)`，其中 `ΔE` 为目标值变差的程度，`T` 为当前温度；
        - 温度 `T` 随调度表 `schedule(t)` 逐步下降；
    - **效果**：高温时接近随机行走（全域探索），低温时近似爬山（局部精化）。理论上，若降温足够慢，SA 以概率 1 找到全局最优。
- **束搜索 (Beam Search)**：
    - **思路**：在 BFS 的每一层中，只保留 `k` 个最有希望的节点继续扩展（`k` 称为**束宽**）；
    - **本质**：在内存受限下的并行搜索——介于贪心（只保留最优 1 个）与穷举（保留全部）之间；
    - **应用**：机器翻译、语音识别等序列生成任务中广泛使用，通常用对数概率作为评分指标。

> **局部搜索与遗传算法的分工**：爬山法、模拟退火、束搜索都属于**单点或短记忆**的局部搜索，擅长在连续或结构化邻域中快速精化。遗传算法则维护一个**种群**，通过选择、交叉、变异在多个区域并行探索，更适合多峰、组合爆炸、约束复杂的优化问题。本节仅对 GA 作概念性速览，其编码策略、选择算子、模式定理与收敛性分析将在第 4 章 §4.1 深入展开。

- **遗传算法 (Genetic Algorithm, GA)（概要，详见第 4 章 §4.1）**：
    - **灵感来源**：自然选择与遗传学——群体的进化过程；
    - **基本流程**：初始化种群（一组候选解）→ 评估适应度 → 选择父代 → 交叉产生子代 → 变异引入多样性 → 形成新一代 → 重复至收敛；
    - **核心操作**：**选择 (Selection)** 按适应度挑选父代（轮盘赌、锦标赛等）；**交叉 (Crossover)** 交换两父代的部分基因（单点、两点、均匀等）；**变异 (Mutation)** 以小概率随机改变基因位以维持多样性。
    - **理论依据**：模式定理 (Schema Theorem) 指出适应度高、定义长度短、阶数低的模式在进化中以指数速率增长。完整的算子设计、GA 变体与多目标进化算法请见第 4 章 §4.1 与 §4.6。

### 2.5 对抗搜索：极小极大算法、Alpha-Beta 剪枝、蒙特卡洛树搜索

- **对抗搜索 (Adversarial Search)** 适用于多智能体环境中**竞争性**的博弈场景——对手的目标与己方相反（零和博弈），搜索时需考虑对手的最优应对。
- **博弈问题形式化**：
    - **初始状态** `S₀`：棋盘初始布局；
    - **玩家函数** `Player(s)`：返回当前轮到谁走；
    - **动作集合** `Actions(s)`：当前状态下合法走法；
    - **转移模型** `Result(s, a)`：走一步后的结果状态；
    - **终局测试** `Terminal-test(s)`：游戏是否结束；
    - **效用函数** `Utility(s, p)`：对局结束时的收益（如国际象棋：赢 +1、输 -1、平 0）。

#### 2.5.1 极小极大算法 (Minimax)

- **核心思想**：MAX 方（我方）试图最大化最终收益，MIN 方（对手）试图最小化——双方交替决策，形成博弈树；
- **递归定义**：设 `v(s)` 为状态 `s` 下 MAX 的最佳收益：
    - 若 `s` 为终局：`v(s) = Utility(s)`；
    - 若 MAX 走：`v(s) = max_{a ∈ Actions(s)} v(Result(s, a))`；
    - 若 MIN 走：`v(s) = min_{a ∈ Actions(s)} v(Result(s, a))`；
- **复杂度**：若博弈树深度为 `d`，分支因子为 `b`，时间 `O(b^d)`，空间 `O(bd)`（深度优先实现）。国际象棋中 `b ≈ 35，d ≈ 100`，穷举完全不可行。

```text
算法：极小极大搜索 (Minimax)
──────────────────────────────────────────────
1.  function Minimax(state) -> 效用值:
2.      if Terminal-test(state): return Utility(state)
3.      if Player(state) == MAX:
4.          return max over a ∈ Actions(state) of Minimax(Result(state, a))
5.      else:  // MIN
6.          return min over a ∈ Actions(state) of Minimax(Result(state, a))
```

**博弈树的评估函数 (Evaluation Function)**：当博弈树无法搜到终局时（深度过大），需在深度限制处用**评估函数** `Eval(s)` 近似 `Utility(s)`。
- **设计要求**：对终局状态的排序应与真实效用一致；计算要足够快（否则不如多搜一层）；能反映局面的关键特征；
- **线性加权模型**：`Eval(s) = w₁ f₁(s) + w₂ f₂(s) + … + wₙ fₙ(s)`，其中 `fᵢ` 为特征，`wᵢ` 为权重。国际象棋常用特征包括子力（兵 1、马/象 3、车 5、后 9）、棋子位置、机动性、王的安全性等；
- **局限**：线性模型难以刻画特征间的非线性相互作用（如"双象优势"、兵形结构）；此外还有**地平线效应 (Horizon Effect)**——看似安全的走法把危机推迟到搜索深度之外，可用**静态搜索 (Quiescence Search)** 缓解。

#### 2.5.2 Alpha-Beta 剪枝 (Alpha-Beta Pruning)

- **核心思想**：在 minimax 搜索过程中，动态维护两个边界：`α`（MAX 的当前最佳选择下界）和 `β`（MIN 的当前最佳选择上界）。当某条路径确定不可能改进当前已找到的最优值时，即可**剪枝**——不再探索该子树；
- **剪枝条件**：若 `v ≥ β`，对 MAX 节点剪枝（β 剪枝），因为 MIN 不会让这种情况发生；若 `v ≤ α`，对 MIN 节点剪枝（α 剪枝），因为 MAX 不会选择这条路；
- **效率提升**：理想情况下（对子节点按最优优先排序），Alpha-Beta 剪枝可将复杂度从 `O(b^d)` 降至 `O(b^(d/2))`——即约等于 Minimax 搜索深度的**两倍**。这意味着在相同时间内可以"多前瞻两步"；
- **节点排序至关重要**：启发式排序（如国际象棋中的吃子优先、杀王优先）可使剪枝效率接近理论最优。

```text
算法：Alpha-Beta 剪枝 (Alpha-Beta Pruning)
──────────────────────────────────────────────
1.  function AlphaBeta(state, α, β) -> 效用值:
2.      if Terminal-test(state): return Utility(state)
3.      if Player(state) == MAX:
4.          v ← -∞
5.          for each a ∈ Actions(state):
6.              v ← max(v, AlphaBeta(Result(state, a), α, β))
7.              if v ≥ β: return v            // β 剪枝：MIN 不会允许
8.              α ← max(α, v)
9.          return v
10.     else:  // MIN
11.         v ← +∞
12.         for each a ∈ Actions(state):
13.             v ← min(v, AlphaBeta(Result(state, a), α, β))
14.             if v ≤ α: return v           // α 剪枝：MAX 不会选择
15.             β ← min(β, v)
16.         return v
```

**复杂度推导：为什么完美排序下是 `O(b^(d/2))`？**
假设每层的最佳走法总是最先被探索。根的第一个（最优）子节点必须完整展开，但它为根确立了很高的 `α` 下界；此后根的其余每个 MIN 子节点，只需考察其第一个（也是最好的）孙子即可触发 α 剪枝，无需展开其余 `b-1` 个孙子。把这一模式逐层递归：每两层实际处理的节点数约为 `b` 个，而非 `b²` 个——也就是**有效分支因子从 `b` 降为 `√b`**。于是总节点数由 `b^d` 变为 `(√b)^d = b^(d/2)`（可证叶节点数约为 `b^(⌈d/2⌉) + b^(⌊d/2⌋) - 1`）。这等价于同一时间预算下**前瞻深度翻倍**。

**数值实例**：设根为 MAX，三个 MIN 子节点 `B、C、D`，叶节点效用如下（从左到右）：

```text
                 MAX
        ┌─────────┼─────────┐
        B         C         D      (MIN)
      ┌─┴─┐    ┌─┴─┐    ┌─┼─┐
      5   6    4   3    7 2 9     (叶)
```

- **Minimax 值**：`B = min(5,6) = 5`，`C = min(4,3) = 3`，`D = min(7,2,9) = 2`，根 `= max(5,3,2) = 5`；
- **Alpha-Beta 执行（α=-∞, β=+∞ 起步）**：
    - 展开 `B`：叶 5 → `B=5`，叶 6 → `B=5`；根 `α=5`；
    - 展开 `C`：叶 4 → `C` 的 `β=4`，此时 `v=4 ≤ α=5` → **α 剪枝**，叶 3 不再访问；
    - 展开 `D`：叶 7 → `β=7`（`7 ≤ 5` 不成立）；叶 2 → `v=2 ≤ α=5` → **α 剪枝**，叶 9 不再访问；
    - 根返回 `max(5,4,2)=5`。
- **结果**：仅评估 5 个叶节点（5、6、4、7、2），跳过了 2 个；剪枝省下的正是"不影响最终决策"的子树。

#### 2.5.3 蒙特卡洛树搜索 (Monte Carlo Tree Search, MCTS)

- **背景**：传统 Minimax（含 Alpha-Beta）依赖评估函数与深度限制，在围棋等大分支因子的游戏中力不从心（`b ≈ 250`）。MCTS 另辟蹊径，不做穷举搜索，而通过**随机模拟（Playout/Rollout）**估计胜率；
- **四步循环**：
    - **选择 (Selection)**：从根节点出发，依据树策略（如 UCB1 公式）选择最有价值的子节点，直至到达**未完全展开的节点**；
    - **扩展 (Expansion)**：若叶节点不是终局，为其添加一个（或多个）子节点；
    - **模拟 (Simulation)**：从新节点出发，执行随机走子（或轻量级策略）直至终局，得到胜负结果；
    - **反向传播 (Backpropagation)**：将模拟结果沿路径向上更新各节点的访问次数与胜率统计；
- **UCB1 公式**：平衡**利用**（高胜率节点）与**探索**（被访问少的节点）：
    `UCT(j) = wⱼ / nⱼ + C · √(ln N / nⱼ)`
    其中 `wⱼ` 为节点 `j` 的获胜次数，`nⱼ` 为访问次数，`N` 为父节点访问次数，`C` 为探索常数；
- **AlphaGo / AlphaZero**：在 MCTS 框架中嵌入深度神经网络——策略网络指导选择与扩展（替代随机走子），价值网络评估局面（替代随机模拟），实现了超越人类世界冠军的水平。AlphaZero 进一步移除人类棋谱依赖，完全通过自对弈学习。

```text
算法：蒙特卡洛树搜索 (MCTS) —— 四步循环
──────────────────────────────────────────────
1.  root ← 以当前局面建立根节点
2.  while 时间预算未耗尽:
3.      // 1. 选择 Selection
4.      node ← 从 root 出发，按 UCT 反复选择子节点，直到到达未完全展开节点
5.      // 2. 扩展 Expansion
6.      if node 不是终局:
7.          node ← 为 node 添加一个新子节点（从未尝试的动作）
8.      // 3. 模拟 Simulation
9.      result ← 从 node 起随机走子（或轻量策略）直至终局
10.     // 4. 反向传播 Backpropagation
11.     沿 node → root 的路径：n ← n + 1，w ← w + result
12. return root 下访问次数 n 最大的子节点所对应的动作
```

### 2.6 约束满足问题（CSP）：回溯搜索、前向检验、弧相容、AC-3 算法

- **约束满足问题 (Constraint Satisfaction Problem, CSP)** 将状态表示为一组**变量**及其**值域**之间的**约束**——搜索目标不再是找到到达目标状态的路径，而是找到一组满足所有约束的变量赋值。CSP 的表示力强，可自然地建模调度、配置、排课、地图着色等大量实际问题。
- **CSP 的三要素**：
    - **变量集合** `X = {X₁, X₂, …, Xₙ}`：待赋值的实体；
    - **值域集合** `D = {D₁, D₂, …, Dₙ}`：每个 `Xᵢ` 的可取值集合（可为离散或连续，但 CSP 通常处理有限离散值域）；
    - **约束集合** `C = {C₁, C₂, …, Cₘ}`：规定变量赋值之间的合法组合——可以是**一元约束**（限制单个变量）、**二元约束**（涉及两个变量，如 `Xᵢ ≠ Xⱼ`）、**全局约束**（涉及多个变量，如 `AllDiff`）。
- **CSP 搜索的特点**：
    - **赋值是交换的**：先给 A 赋值再给 B 赋值，与相反顺序的结果相同，因此 CSP 不必考虑路径——只需按变量顺序赋值即可，搜索空间缩小为 `O(dⁿ)` 而非 `O(n! · dⁿ)`；
    - **回溯搜索 (Backtracking Search)**：基本 CSP 求解算法，每次选择一个未赋值的变量，尝试其值域中的每个可能值，若当前赋值与约束冲突则回溯。本质是**带剪枝的深度优先搜索**；
    - **与经典搜索的区别**：CSP 的"状态"是部分赋值（而非世界状态的快照），"目标测试"是对所有变量赋值完毕且所有约束成立。

#### 2.6.1 具体实例：地图着色与任务调度

- **地图着色 (Map Coloring)**：给定一张地图，用有限种颜色为每个区域着色，使相邻区域颜色不同。以澳大利亚为例，变量为 `{WA, NT, SA, Q, NSW, V, T}`，值域均为 `{红, 绿, 蓝}`，二元约束为"相邻区域颜色不等"，即 `WA ≠ NT, WA ≠ SA, NT ≠ SA, NT ≠ Q, SA ≠ Q, SA ≠ NSW, SA ≠ V, Q ≠ NSW, NSW ≠ V`（T 与大陆隔离，可单独处理）。该问题有解，例如 `WA=红, NT=绿, SA=蓝, Q=红, NSW=绿, V=红, T=红`。
- **任务调度 (Job Scheduling)**：设有课程 `A、B、C、D`，每门课有可选时间段，约束包括"同一教师的两门课不能同时段""同一教室同一时段只能排一门课""先修课需排在后续课程之前"等。以二元约束 `C(X, Y)` 表示"`X` 的时段必须早于 `Y`"，即可用 CSP 统一求解。
- **回溯搜索的直观轨迹（Australia）**：按 `WA → NT → SA → Q → NSW → V` 顺序赋值，采用最浅一致值优先：
    - `WA = 红`；
    - `NT ≠ WA`，取 `NT = 绿`；
    - `SA ≠ WA, SA ≠ NT`，只剩蓝色，取 `SA = 蓝`；
    - `Q ≠ NT, Q ≠ SA`，可取红，取 `Q = 红`；
    - `NSW ≠ Q, NSW ≠ SA`，可取绿，取 `NSW = 绿`；
    - `V ≠ SA, V ≠ NSW`，取红，成功。
    若在中途发现某变量值域为空，则回溯到最近的可改选择点。

```text
算法：CSP 回溯搜索 (Backtracking Search)
──────────────────────────────────────────────
1.  function Backtrack(assignment):
2.      if assignment 已为所有变量赋值: return assignment
3.      var ← Select-Unassigned-Variable(csp, assignment)     // 如 MRV
4.      for each value ∈ Order-Domain-Values(var, assignment): // 如 LCV
5.          if value 与 assignment 一致:
6.              assignment ← assignment ∪ {var = value}
7.              inferences ← Inference(csp, var, value)        // 如 FC / AC-3
8.              if inferences ≠ failure:
9.                  result ← Backtrack(assignment ∪ inferences)
10.                 if result ≠ failure: return result
11.             assignment ← assignment \ {var = value}          // 撤销赋值
12.     return failure
```

- **约束传播 (Constraint Propagation)**：
    - **核心思想**：在搜索过程中（甚至在搜索前），利用约束缩小变量的值域，提前排除不可能的值，减少无效搜索；
    - **前向检验 (Forward Checking, FC)**：为某一变量赋值后，立即检查所有尚未赋值的邻居变量，移除与其冲突的值——若某变量的值域因此变空，立即回溯。FC 是回溯搜索最常见的第一道防线；
    - **弧相容 (Arc Consistency, AC)**：对于二元约束 `C(X, Y)`，称边 `X → Y` 为**弧相容**的，当且仅当对 `X` 值域中每个值，在 `Y` 的值域中都存在至少一个值使得 `C` 被满足。AC 比前向检验传播得更远（考虑非直接邻居）；
    - **AC-3 算法**：最广泛使用的弧相容算法，将所有弧放入队列，依次检查每条弧是否相容——若某条弧不相容则删除对应值并重新将受影响的弧入列，直到队列为空。复杂度 `O(cd³)`（`c` 为约束数，`d` 为最大值域大小）；
    - **k-相容性 (k-Consistency)**：将相容性推广——1-相容（节点相容，每个值满足一元约束）、2-相容（弧相容）、强 k-相容（对所有 `i ≤ k` 均为 i-相容的）——更强的传播可进一步缩窄搜索空间，但计算代价相应增大。

```text
算法：AC-3 弧相容
──────────────────────────────────────────────
1.  queue ← 所有弧 (Xi, Xj) 的集合
2.  while queue 非空:
3.      (Xi, Xj) ← queue.pop()
4.      if Revise(csp, Xi, Xj):              // D(Xi) 有删减则返回 true
5.          if D(Xi) == ∅: return false      // 值域为空，CSP 无解
6.          for each Xk ∈ neighbors(Xi) \ {Xj}:
7.              queue.push((Xk, Xi))          // 重新检查指向 Xi 的弧
8.  return true

function Revise(csp, Xi, Xj):
1.  revised ← false
2.  for each x ∈ D(Xi):
3.      if 不存在 y ∈ D(Xj) 使约束 C(Xi, Xj) 成立:
4.          D(Xi) ← D(Xi) \ {x}
5.          revised ← true
6.  return revised
```

**AC-3 执行轨迹（小实例）**：设变量 `X、Y、Z`，值域 `D(X)={1,2}`、`D(Y)={1,2}`、`D(Z)={1,2,3}`，约束为 `X ≠ Y` 与 `Y < Z`。

| 步骤 | 出队弧 | 检查结果 | 值域变化 | 重新入队 |
|:---:|:---|:---|:---|:---|
| 1 | `(X, Y)` | 每个 `x` 都有 `y ≠ x`（1↔2、2↔1） | 无 | — |
| 2 | `(Y, X)` | 对称，每个 `y` 都有 `x ≠ y` | 无 | — |
| 3 | `(Y, Z)` | `y=1→z=2/3`，`y=2→z=3` | 无 | — |
| 4 | `(Z, Y)` | `z=1` 无 `y < 1`；`z=2→y=1`，`z=3→y=1/2` | `D(Z)={2,3}`（删 1） | `(Y, Z)` |
| 5 | `(Y, Z)` | `y=1→z=2`，`y=2→z=3` | 无 | — |
| 6 | 队列空 | 所有弧均相容 | `D(Z)={2,3}` | — |

弧相容提前排除了 `Z=1`，使后续搜索空间缩小；若某步骤出现值域为空，则说明该 CSP 无解，可立即失败。

- **变量与值的选择启发式**：
    - **最小剩余值 MRV (Minimum Remaining Values)**：选择当前值域最小的变量——即最可能受限的变量优先（"最易失败的先处理"）；
    - **度启发式 (Degree Heuristic)**：当 MRV 平局时，选择与其他未赋值变量约束最多的变量——最具影响力的先处理；
    - **最少约束值 (Least Constraining Value)**：选择给邻居变量留下最大选择余地的值——"留有余地"的值优先。
- **回溯搜索的改进**：
    - **回跳 (Backjumping)**：当在某变量值域全部尝试后均失败时，不是简单回溯到上一层，而是智能地跳回导致冲突的根源变量（冲突集分析）；
    - **学习 (Learning)**：将导致失败的赋值组合记录为新的约束（**诺戈德 NoGood**），避免将来重复尝试同样组合。

### 2.7 本章小结

**核心要点回顾**

- **问题形式化**：任何搜索问题都可用五要素（初始状态、动作、转移模型、目标测试、路径代价）刻画；状态空间图是问题固有的，搜索树是算法动态构建的。
- **无信息搜索**：BFS（FIFO，等代价最优但空间 `O(b^d)`）、DFS（LIFO，省内存但不完备非最优）、DLS/IDS（深度限制 + 迭代加深，兼顾完备与省内存）、UCS（优先队列，按 `g` 扩展，完备且最优）。
- **有信息搜索**：贪心搜索只看 `h`，A* 兼顾 `g + h`；`h` 可纳 ⇒ A* 最优，`h` 一致 ⇒ 每节点最多扩展一次且顺序最优；A* 在其启发式下"最优效率"最高。IDA* 用阈值迭代把 A* 的空间降到 `O(bd)`。
- **启发式设计**：松弛问题、模式数据库、支配关系与学习是四条主要路径；对八数码，曼哈顿距离支配错位棋子数。
- **局部搜索**：爬山法易陷局部最优/高原/山脊，随机重启与模拟退火可缓解；束搜索在内存受限下折中；遗传算法属种群进化方法，详见第 4 章 §4.1。
- **对抗搜索**：Minimax 递归 max/min，Alpha-Beta 用 `α/β` 剪枝把复杂度降到 `O(b^(d/2))`，评估函数与节点排序决定实战效果；MCTS 以选择-扩展-模拟-反向传播四步循环估计胜率，AlphaGo/AlphaZero 将其与深度网络结合。
- **CSP**：以变量、值域、约束建模；回溯搜索 + MRV/度启发式/LCV + 前向检验 + AC-3 弧相容是最常用的组合；AC-3 反复修订弧直至队列为空，可提前发现无解。
