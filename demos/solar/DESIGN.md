# Solar — 设计文档

## 1. 目标与约束

| 目标 | 决定 |
| --- | --- |
| 「真实数据」 | 位置由**开普勒方程**从真实轨道要素求解，而不是匀速圆周运动；半径、质量、自转、转轴指向均取观测值 |
| 「真实比例」 | 1 世界单位 = 1 AU，轨道距离与天体半径都不做缩放；唯一的放大滑块默认 1×（关闭） |
| 「尽量完整」 | 太阳 + 8 行星 + 5 矮行星 + 4 主带小行星 + 2 彗星 + 23 卫星 + 两条带 |
| 「有贴图」 | 真实行星贴图（Solar System Scope, CC BY 4.0），缺失者程序化生成 |
| 「方便放大与定位」 | 侧栏天体树 + 屏幕标签 + 点击拾取 + 对数距离滑块 + URL 深链 |
| 「双击可看」 | `npm run build` 产出单个自包含 HTML |

### 真实比例带来的核心可用性问题

太阳半径 695 700 km ≈ 0.00465 AU，海王星轨道 30 AU，比值约 6 500。
在 1 680×950 的视口里看全景（约 67 AU）时：

| 天体 | 投影半径 |
| --- | --- |
| 太阳 | 0.07 px |
| 木星 | 0.007 px |
| 地球 | 0.0006 px |

**因此「用肉眼在 3D 视图里找到行星」在这个尺度上是不可能的**，必须靠
导航与标注解决，而不是靠修改比例。设计上采取：

1. **名称牌（CSS2D）**始终锚定在天体中心并显示，作为定位手段；
2. **标记点尺寸严格等于天体投影直径**，不设任何上下限——缩小时一直缩到看不见，
   绝不留下固定尺寸的点（否则相对大小会被拉平，出现「太阳比行星还小」）；
3. 侧栏可搜索的天体树作为主入口；
4. `#bodyId` 深链；
5. 对数距离滑块（1.5 km – 600 AU）配合滚轮，跨越 14 个数量级。

## 2. 参考系与数学

### 2.1 坐标系

内部**只用一套坐标**：J2000 平黄道与春分点直角坐标（+x 指向春分点，
+z 指向黄道北极），单位 AU。`core/` 中没有任何 three.js 依赖，可直接单测。

渲染层做一次映射：`(x, y, z)_ecl → (x, z, −y)_three`，使黄道面成为 three.js 的
XZ 平面、黄道北成为 +Y。

### 2.2 轨道传播

统一用六要素 `(a, e, i, L, ϖ, Ω)`，两种传播方式：

- **行星**：Standish & Williams 的要素 + 世纪变率（`rates`），有效 1800–2050；
- **其他天体**：某历元的瞬时要素 + 固定平均运动（开普勒第三定律，
  或卫星显式给出的恒星周期）。

求解流程（Standish & Williams 步骤 1–5）：

```
T   = (JD − 2451545) / 36525
a,e,i,L,ϖ,Ω ← 要素 (+ 变率)
ω   = ϖ − Ω ,  M = L − ϖ
E   ← 解 Kepler 方程  M = E − e·sin E
x'  = a(cos E − e) ,  y' = a√(1−e²)·sin E
r   ← Rz(−Ω)·Rx(−I)·Rz(−ω)·(x', y', 0)
```

Kepler 方程用 **Newton–Raphson + 二分兜底**：高偏心彗星（e ≈ 0.968）在近日点
附近 Newton 收敛很慢，二分保证有界收敛（`E ∈ [M−e, M+e]`）。

### 2.3 姿态

- 自转轴：优先使用 **IAU 极轴 (RA, Dec)**，经黄赤交角 ε=23.43928° 转到黄道系；
  没有极轴数据的天体退化为「绕春分点轴倾斜 obliquityDeg」。
- 自转：`θ = 2π (JD − J2000) / P_sidereal`，绕自身北极轴。
- 扁率：`scale = (r_eq, r_eq(1−f), r_eq)`，木星 f=0.065、土星 f=0.098。
- 卫星：其轨道要素定义在母星赤道（或拉普拉斯）面内，用母星倾斜四元数旋转到黄道系。

### 2.4 月球

月球不用平均要素，而用 Schlyter 摄动理论（平轨道 + 出差、二均差、年差、
视差不等共 12 个主要周期项），地心距离精度优于 1%、方向优于 1.5°
（对拍 JPL Horizons 地心矢量验证）。

## 3. 模块划分

```
core/   纯函数与纯数据模型，零图形依赖，Vitest 直接测试
  ↑
data/   真实数据常量 + 脚本生成的卫星轨道表
  ↑
scene/  three.js：几何、材质、相机、拾取
ui/     原生 DOM 面板
app.ts  装配 + 主循环 + 快捷键
```

`core/model.ts` 是唯一的真相来源：给定 JD，一次遍历（父体先于子体）算出
每个天体的日心位置、相对母体位置、极轴单位向量与自转相位。

## 4. 渲染要点

| 问题 | 方案 |
| --- | --- |
| 深度精度跨越 10¹² 倍 | `logarithmicDepthBuffer: true` + 每帧按「相机到焦点距离」动态调整近裁剪面 |
| 远景不可见 | 名称牌 + 严格等比标记点 + 侧栏导航（见 §1） |
| 光照 | 太阳处 `PointLight(decay = 0)`：保留昼夜分界线的方向正确性，同时避免平方反比让外行星不可见 |
| 距离跨度导致滚轮难用 | `zoomSpeed = 4.5`（每格 ≈ 1.25×）；视口级非被动 `wheel` 监听确保只缩放相机、永不缩放网页 |
| 标签遮挡/抖动 | CSS2D 拆成「标记点」与「名称牌」两个对象，锚点都固定在天体中心，切换显示不会位移 |
| 光环 | `RingGeometry` 重写 UV 使 u = 径向比例（贴图是 2048×125 的径向剖面），`rotation.x = −π/2` 躺入赤道面 |
| 性能 | 卫星球体低分段；两条带用 `Points(sizeAttenuation:false)` 并以 4 Hz 节流更新 |

## 5. 数据流水线

```
JPL Horizons ─┐
JPL SBDB     ─┼→ scripts/fetch-reference.mjs → reference/*.json ─┐
JPL 卫星表   ─┴→ scripts/fetch-satellites.mjs ─→ parse ──────────┤
                                                                 ├→ src/data/*.ts
Solar System Scope → masters/textures/ → optimize-textures ──────┤
                                                                 └→ src/assets/textures/
src/data/moon-orbits.generated.ts ← scripts/gen-moon-orbits.mjs ←┘
```

所有脚本支持断点续传（按文件缓存），单点失败不会中断，重跑即可补齐。
抓取到的原始数据全部留在 `reference/`，便于审计与复现。

## 6. 测试策略

| 测试 | 内容 |
| --- | --- |
| `kepler.test.ts` | Kepler 方程残差 < 1e-9（e 从 0 到 0.968）；平均运动与开普勒第三定律；轨道闭合；近日点/远日点落在 1 月/7 月 |
| `horizons.test.ts` | 8 大行星在 2000 / 2025 / 2050 三个历元对拍 Horizons，角度与径向误差断言在 Standish 标称精度内；冥王星单独以 1% 为上界 |
| `lunar.test.ts` | 月球地心距离误差 < 1%、方向 < 1.5°；近地点/远地点幅度合理 |

## 7. 构建策略

- **开发 / 服务器构建**（`npm run dev` / `build:server`）：贴图作为普通资源文件。
- **单文件构建**（`npm run build`，默认）：`format: 'iife'` + CSS/JS 内联 +
  `assetsInlineLimit: Infinity` 把贴图内联为 data URL，产出单个可双击打开的 HTML。
  内联脚本被移动到 `</body>` 之前（行内脚本没有 `defer`），文本替换使用函数式
  `String.replace` 以避免 `$&` 被当作替换模式。

选择内联贴图而非常规资源文件，是因为 `file://` 下浏览器会以 CORS 拒绝外部图片，
且被污染（tainted）的图片无法上传为 WebGL 纹理——内联 data URL 是唯一可靠方案。
